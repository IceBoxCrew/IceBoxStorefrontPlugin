<a id="1-overview"></a>
## 1. Обзор

Storefront-плагин — это нативный плагин на C++ (`Steam.dll` / `Steam.so` / `Steam.dylib`), который компонуется со
**Steamworks SDK**. Когда движок его загружает, плагин:

1. Определяет ваш Steam **AppId** (см. [Настройка AppId](#configuring-your-appid)).
2. Инициализирует `SteamAPI` и проверяет, что локальный пользователь вошёл в клиент Steam.
3. Регистрирует глобальную таблицу Lua **`Storefront`** в каждом состоянии Lua, которое создаёт движок.
4. **Каждый кадр** автоматически прокачивает колбэки Steam и доставляет поставленные в очередь результаты в Lua
   (вам **не** нужно самостоятельно вызывать ни `SteamAPI_RunCallbacks`, ни `Storefront.Tick()`).

Весь игровой код общается со Steam через таблицу `Storefront`. Таблица по своей сути **не зависит от бэкенда**:
основная поверхность (достижения, статистика, таблицы лидеров, облако, друзья, лобби, P2P, DLC) смоделирована как
обобщённый «storefront», а поверх неё расположен набор **специфичных для Steam** расширений (Steam Deck, Мастерская,
Steam Input, голос, билеты аутентификации, диалоги приглашений оверлея).

> **Платформа:** только настольные ОС — **Windows**, **Linux**, **macOS**. Steamworks SDK работает только на
> настольных платформах, поэтому в сборках для Android, iOS и Web (Emscripten) плагин полностью пропускается. Всегда
> защищайте код Steam вызовом [`Storefront.IsAvailable()`](#41-storefrontisavailable), чтобы одни и те же скрипты
> без изменений работали на других платформах.

> **Требуется клиент Steam:** функции Steam работают только тогда, когда игра запущена **через работающий клиент
> Steam** аккаунтом, который **владеет данным AppId**. На этапе разработки см. [`steam_appid.txt`](#steam_appidtxt-for-development).

<a id="2-installation--setup"></a>
## 2. Установка и настройка

<a id="where-the-plugin-lives"></a>
### Где находится плагин

Как и любой плагин IceBox, Storefront-плагин — это папка внутри каталога `Plugins/` вашего проекта. Она
называется `Steam` — по имени бэкенда, который плагин предоставляет, — и движок опознаёт плагин именно по нему:

```
Plugins/
└── Steam/
    ├── Steam.dll            ← скомпилированный плагин (зависит от платформы, из релиза)
    ├── steam_api64.dll      ← среда выполнения Steamworks (кладёте сюда вы, от Valve)
    ├── plugin.json          ← манифест плагина
    ├── VisualScriptAPI.json ← каталог нод (обязателен во время выполнения)
    ├── icon.png             ← иконка плагина для редактора и лаунчера
    └── steam_config.json    ← ваш AppId (вы создаёте этот файл)
```

Движок автоматически обнаруживает папку, загружает её при включении, каждый кадр вызывает `OnUpdate` и привязывает
таблицу `Storefront` к Lua. Включать и отключать плагины можно на панели **Plugins** в редакторе.

> **Библиотека среды выполнения Steam.** Она лежит в папке плагина, рядом со `Steam.dll` / `Steam.so` /
> `Steam.dylib`, на **всех трёх десктопных платформах** — это единственное место, с которым согласны все
> динамические загрузчики. На Windows плагин загружает её оттуда явно; на Linux плагин несёт RPATH `$ORIGIN`;
> на macOS `libsteam_api.dylib` собран с install name `@loader_path/libsteam_api.dylib` и *обязан* лежать рядом
> с библиотекой, которая его линкует. Движок выбирает библиотеку плагина по совпадению имени с именем плагина,
> поэтому рантайм в той же папке никогда не будет принят за сам плагин. Вы кладёте его туда один раз, скопировав
> из собственной загрузки Steamworks SDK — точный файл под каждую платформу указан в `README.md`.

> ⚠️ **Теперь эта папка самодостаточна для *вас* — и передавать её дальше нельзя.** `steam_api64.dll` /
> `libsteam_api.so` / `libsteam_api.dylib` взяты из SDK Valve, а Valve лицензирует этот SDK вам **без права
> передачи**. Он может уехать внутри игры, которую вы выпускаете игрокам, — это Valve разрешает, — но его
> **не должно** быть ни в чём, что вы отдаёте другому разработчику. Самого плагина это касается тоже: он
> бесплатный, но перезаливать его нельзя (Раздел 4.1 в `LICENSE.txt`). Отправьте коллегу на официальную страницу
> загрузки — он получит ту же сборку за минуту и бесплатно. Полный список — в `DISTRIBUTION.md`.

<a id="the-steamworks-sdk"></a>
### Steamworks SDK

**Steamworks SDK не поставляется** вместе с плагином, и ни одна его часть не может распространяться вместе с
плагином — каждый разработчик скачивает его с
[партнёрского сайта Steamworks](https://partner.steamgames.com/doc/sdk), принимая по пути *Steamworks SDK Access
Agreement* от Valve. Valve лицензирует SDK этому разработчику напрямую; IceBoxCrew Studio не является стороной
этого соглашения и ничего по нему не сублицензирует.

Из этой загрузки вам нужен **ровно один файл** — библиотека среды выполнения Steam, — и вы кладёте её в папку
плагина один раз:

| Платформа | Файл | Откуда |
| --- | --- | --- |
| Windows x64 | `steam_api64.dll` | `redistributable_bin/win64/` |
| Linux x64 | `libsteam_api.so` | `redistributable_bin/linux64/` |
| macOS | `libsteam_api.dylib` | `redistributable_bin/osx/` |

Заголовки и импортная библиотека нужны только тому, кто компилирует плагин, а это не вы: плагин приходит уже
собранным. При **выпуске вашей игры** скомпилированная библиотека `Steam` и этот рантайм едут внутри вашего
пакета, что разрешает Раздел 1.1 вашего собственного соглашения с Valve: они уходят вместе с вашим приложением.

> **Минимальная версия SDK: v1.65.** Плагин использует `ISteamUtils::IsRunningOnSteamHardware()`,
> `GetSteamHardwareDefaultConfig()` и `IsRunningUnderProton()` — они появились в v1.65 вместе с удалением
> `IsRunningOnSteamDeck()`. Берите библиотеку среды выполнения из архива SDK v1.65 или новее.

<a id="configuring-your-appid"></a>
### Настройка AppId

При загрузке плагин определяет Steam AppId из первого источника, дающего ненулевое значение, в следующем порядке:

1. Переменная окружения **`ICEBOX_STEAM_APPID`**.
2. **`steam_config.json` в собственной папке плагина** — JSON-файл с полем `"AppId"`. Движок сообщает плагину, откуда
   тот был загружен, поэтому это работает независимо от имени папки и от того, лежит плагин в `Plugins/` движка или
   проекта.
3. **`Plugins/Steam/steam_config.json`** относительно рабочего каталога.
4. **`steam_config.json`** в рабочем каталоге.
5. **`steam_appid.txt`** (обычный текстовый файл, содержащий только число) — ищется в тех же трёх местах.

Рекомендуемый способ — `steam_config.json`:

```json
{
    "AppId": 480
}
```

> `480` — это публичный тестовый AppId **Spacewar** от Valve, удобный для проверки функций Steam до того, как для
> вашего собственного приложения будет выделен AppId. Замените его на свой реальный AppId для продакшена.

Если AppId определить **не** удалось, плагин пишет сообщение в лог движка и **не регистрирует бэкенд storefront** —
`Storefront.IsAvailable()` возвращает `false`, и каждый вызов становится безопасной пустой операцией. Ваша игра
по-прежнему работает. То же самое происходит, если не удалось инициализировать сам `SteamAPI` (Steam не запущен,
аккаунт не владеет приложением и т. п.), поэтому отсутствующая или сломанная настройка Steam никогда не уронит игру.

<a id="steam_appidtxt-for-development"></a>
### `steam_appid.txt` для разработки

Когда вы запускаете игру **из редактора или напрямую как исполняемый файл** (а не через Steam), клиенту Steam нужна
подсказка о том, каким приложением вы являетесь. На время разработки положите рядом с исполняемым файлом
`steam_appid.txt`, содержащий только ваш AppId:

```
480
```

Удалите его из релизных сборок — при запуске вашей игры рабочий клиент Steam сам предоставит AppId.

<a id="restarting-through-steam"></a>
### Перезапуск через Steam

Steam-сборка должна быть **запущена именно Steam**, иначе не будет ни оверлея, ни облака, ни DRM, ни всплывающих
уведомлений о достижениях. Игрок, сделавший ярлык прямо на `.exe`, иначе получил бы молча урезанную игру.

**Выпущенная игра делает это за вас.** До старта движка — до окна, до любого скрипта — рантайм выполняет ранний
хук каждого включённого плагина. Хук Steam-плагина определяет ваш AppId и вызывает
`SteamAPI_RestartAppIfNecessary`; если Steam должен перезапустить игру, процесс немедленно завершается, и Steam
запускает её заново как надо. Ничего вызывать и подключать не нужно.

В редакторе он сознательно **не** выполняется: перезапуск через Steam там убил бы вашу сессию редактора.

Три способа его отключить, в порядке приоритета:

| Способ | Эффект |
|--------------|--------|
| `steam_appid.txt` рядом с экзешником | Steam считает процесс уже запущенным, и проверка проходит насквозь. Это и есть рабочий процесс разработки. |
| `ICEBOX_STEAM_NO_RESTART=1` в окружении | Пропускает проверку для конкретного запуска. |
| `"RestartIfNecessary": false` в `steam_config.json` | Пропускает проверку насовсем для этой сборки — используйте для DRM-free сборки той же игры, которая должна работать сама по себе. |

```json
{
    "AppId": 480,
    "RestartIfNecessary": true
}
```

> **Используете DRM-обёртку Valve?** Тогда проверка избыточна — обёртка и так гарантирует корректный запуск.
> Оставить её включённой безвредно (она вернёт «действий не требуется»), но можно выставить
> `"RestartIfNecessary": false`.

> **Для чего эти переключатели — и для чего они не предназначены.** Все три существуют ради двух законных задач:
> запускать вашу собственную игру из редактора или напрямую из экзешника, пока вы её разрабатываете, и выпускать
> DRM-free-сборку вашей же игры в магазин, не являющийся Steam. Это не способ запустить чужую игру, не владея ею:
> ни один из них не обходит DRM-обёртку Valve, а Steam-сборка без лицензии просто не инициализируется.
> `steam_appid.txt` в особенности: его место — рядом с вашей сборкой на вашей машине и больше нигде. Его не должно
> быть ни в пакете, который вы загружаете в Steam, ни в пакете плагина, который вы отдаёте другому разработчику.

[`Storefront.RestartAppIfNecessary(appId)`](#185-storefrontrestartappifnecessary) по-прежнему доступна на редкий
случай, когда вы хотите управлять проверкой сами, но вызов из скрипта уровня слишком поздний, чтобы быть основным
механизмом — Steam к тому моменту уже инициализирован.

### Что попадает в вашу игру, а что попадать не должно

**Tools → Build Game** в редакторе переносит папку `Plugins/` вашего проекта в игру, а затем накладывает поверх
скомпилированные бинарники плагинов. Несколько вещей стоит знать:

- **`Config/Plugins.json` решает, что реально загрузится.** Плагин, который присутствует, но не отмечен там как
  включённый, будет обнаружен и проигнорирован. Включите **Steam** один раз на вкладке Plugins в редакторе — это
  запишет файл, а сборка его скопирует. Без этого в выпущенной игре плагин лежит на диске, а интеграции со Steam
  нет вообще.
- **`steam_appid.txt` не должен попадать в релиз.** Он говорит Steam «считай, что AppId такой, проверка запуска не
  нужна» — ровно то, что нужно на вашей машине, и ровно то, что не нужно в релизе. Держите его рядом со собранным
  экзешником при тестировании и удаляйте из пакета, который выкладываете.
- **Библиотека среды выполнения Steam едет вместе с плагином.** `steam_api64.dll` / `libsteam_api.so` /
  `libsteam_api.dylib` разворачивается в папку плагина рядом с `Steam.dll`/`.so`/`.dylib` на всех десктопных
  платформах — это единственное место, с которым согласны все три динамических загрузчика. Не перемещайте её.
- **Всё остальное из папки плагина тоже попадает в сборку**, включая `Documentation/`. Если оставить, ничего не
  сломается, но это примерно 400 КБ markdown, который вам вряд ли нужен в релизе — удалите его из подготовленного
  вывода (или из `Plugins/Steam/` вашего проекта), если размер пакета важен. `LICENSE.txt`, `NOTICE.md` и
  `THIRD_PARTY_NOTICES.txt` остаются: последний закрывает требования атрибуции sol2, Lua, nlohmann/json и fmt, и
  весит несколько килобайт.

<a id="shipping-the-plugin-itself"></a>
### Передать *плагин* другому разработчику — это другой вопрос, и ответ на него: нельзя

Всё выше — про **вашу игру**, которая уходит к **игрокам**. Передать папку плагина другому разработчику —
выложить на itch.io, GitHub, маркетплейс, в пак ассетов или архивом в чат — это отдельная ситуация, и ответ там
короткий: **нет**.

| | Уезжает с вашей **игрой** | Уезжает другому **разработчику** |
|---|---|---|
| `Steam.dll` / `.so` / `.dylib` (плагин) | ✅ обязательно | 🚫 нет — дайте ссылку на загрузку |
| `plugin.json`, `VisualScriptAPI.json`, `icon.png` | ✅ обязательно | 🚫 нет |
| `LICENSE.txt`, `NOTICE.md`, `THIRD_PARTY_NOTICES.txt` | ✅ оставьте в папке | — |
| `Documentation/`, `README.md` | по желанию | — |
| `steam_api64.dll` / `libsteam_api.so` / `libsteam_api.dylib` | ✅ да — Valve это разрешает | 🚫 **никогда** |
| `steam_config.json` | ✅ да — игра читает из него AppId | 🚫 никогда — там *ваш* AppId |
| `steam_appid.txt` | 🚫 никогда — удалите перед загрузкой | 🚫 никогда |

За правым столбцом стоят две отдельные причины.

**Библиотека среды выполнения принадлежит Valve.** Раздел 1.1 *Steamworks SDK Access Agreement* разрешает вам
распространять содержимое папки `redistributable_bin` из SDK **вместе с вашим собственным приложением** — именно
это делает её законной внутри выпущенной игры. Это разрешение **не передаётся дальше**: оно не переходит к тому,
кому вы отдали копию. Он берёт SDK у Valve сам — что любой Steam-разработчик и так делает.

**Сам плагин принадлежит нам.** Он ничего не стоит и при этом не open source. Перезаливать его — на другой сайт,
в маркетплейс, в пак ассетов, внутри изменённой сборки движка, за деньги или без — не разрешено; юридически
значимая формулировка — Раздел 4.1 в `LICENSE.txt`. Внутри вашей игры он ездит свободно, и это Раздел 2.2. Тот, кому плагин
нужен, берёт его на официальной странице загрузки за минуту, бесплатно и в той сборке, которая соответствует его
версии движка, — а это, к тому же, единственный способ получить ту, которая вообще загрузится.

`DISTRIBUTION.md` в корне плагина содержит полный перечень того, что попадает в заливаемый билд, и того, чего в
нём быть не должно.

<a id="3-core-concepts"></a>
## 3. Основные концепции

<a id="the-storefront-table"></a>
### Таблица `Storefront`

Всё доступно через одну глобальную таблицу:

```lua
Storefront.UnlockAchievement("ACH_WIN_ONE_GAME")   -- функция верхнего уровня
Storefront.Workshop.GetSubscribed()                 -- подтаблица Мастерской
Storefront.Input.GetControllers()                   -- подтаблица Steam Input
Storefront.Result.Ok                                -- константа перечисления
```

- **Функции верхнего уровня** покрывают независимую от бэкенда поверхность плюс расширения Steam.
- **`Storefront.Workshop.*`** группирует все функции Мастерской Steam (UGC).
- **`Storefront.Input.*`** группирует все функции Steam Input (контроллер / Steam Deck).
- Таблицы **`Storefront.<ИмяПеречисления>`** содержат целочисленные константы перечислений (например, `Storefront.Result`, `Storefront.LobbyType`).

<a id="the-frame-tick--storefronttick"></a>
### Покадровый тик — `Storefront.Tick()`

> **Чтобы API работал, вызывать ничего не нужно.** Плагин каждый кадр сам прокачивает нативные колбэки Steam **и**
> сбрасывает очередь колбэков Lua из своего шага обновления в движке, пока работает рантайм.

Результаты асинхронных вызовов (`FindOrCreateLeaderboard`, `CreateLobby`, `Workshop.CreateItem`, …) и обработчики
событий (`OnP2PMessage`, `OnAchievementUnlocked`, …) **ставятся в очередь** на нативной стороне и доставляются в Lua
в главном потоке, на шаге обновления плагинов — до того, как в этом кадре выполнятся ваши `OnUpdate` уровня и
сущностей.

`Storefront.Tick()` остаётся доступным как **явный необязательный** сброс очереди — вызывайте его, когда хотите
опустошить очередь в конкретной точке своего кадра (например, прямо перед чтением `Storefront.ReceiveP2P()` в
сетевом цикле) или в коде, написанном под более раннюю версию плагина:

```lua
-- Необязательно. В скрипте уровня (.icemap) или в долгоживущей сущности-менеджере:
function OnUpdate(dt)
    Storefront.Tick()
end
```

`Storefront.Tick()` дёшев, безопасен при повторном входе, идемпотентен и ничего не делает, когда активного бэкенда
нет или очередь уже пуста, поэтому вызывать его всегда безопасно — и так же безопасно не вызывать.

<a id="result-codes"></a>
### Коды результата

Функции, изменяющие состояние, возвращают **целочисленный код результата** из перечисления `Storefront.Result`.
`0` (`Ok`) означает успех; положительная `1` (`Pending`) означает «принято, ещё в процессе»; **отрицательные
значения — это ошибки**.

```lua
local r = Storefront.UnlockAchievement("ACH_WIN_ONE_GAME")
if r == Storefront.Result.Ok then
    Print("Разблокировано!")
else
    Print("Ошибка: " .. Storefront.ResultName(r))   -- например, "NotLoggedIn"
end
```

Используйте [`Storefront.ResultName(code)`](#412-storefrontresultname), чтобы превратить код в читаемую строку для
логирования. См. [полную таблицу кодов результата](#result-enum).

<a id="synchronous-vs-asynchronous-calls"></a>
### Синхронные и асинхронные вызовы

- **Синхронные** функции возвращают результат немедленно — значение, таблицу или код `Result`. Примеры:
  `UnlockAchievement`, `GetFriends`, `CloudWrite`, `SetLobbyData`.
- **Асинхронные** функции принимают **функцию-колбэк** в качестве последнего аргумента и ничего не возвращают.
  Колбэк выполняется позже (в том кадре, когда пришёл результат, — во время обновления плагина или ручного
  `Storefront.Tick()`), получая код `Result` плюс какие-либо данные. Примеры:
  `FindOrCreateLeaderboard`, `DownloadLeaderboardEntries`, `CreateLobby`, `JoinLobby`, `SearchLobbies`,
  `RequestNumberOfCurrentPlayers`, `RequestAuthSessionTicket` и весь набор `Workshop.*`.

```lua
-- Асинхронно: результат приходит в колбэке, в одном из последующих кадров.
Storefront.FindOrCreateLeaderboard("HighScores",
    Storefront.LeaderboardSort.Descending,
    Storefront.LeaderboardDisplay.Numeric,
    function(result, handle)
        if result == Storefront.Result.Ok then
            Print("Хэндл таблицы лидеров: " .. handle)
        end
    end)
```

Колбэки всегда вызываются в главном потоке, из покадрового сброса очереди плагином (или из ручного
`Storefront.Tick()`). Из колбэка безопасно вызывать другие функции `Storefront`.

<a id="the-userhandle-table"></a>
### Таблица `UserHandle`

Пользователи Steam (локальный игрок, друзья, участники лобби, владельцы записей таблиц лидеров, отправители P2P)
представлены небольшой таблицей **`UserHandle`**:

| Поле | Тип | Описание |
|-------|------|-------------|
| `backend` | `int` | Идентификатор бэкенда — `1` для Steam (см. [`Storefront.Backend`](#backend-enum)). |
| `id` | `int` | 64-битный SteamID в виде целого числа. |
| `textId` | `string` | Тот же SteamID64 в виде десятичной строки (безопасно для отображения / хранения). |

Везде, где функции нужно идентифицировать пользователя (например, `SendP2P`, `ActivateOverlayToUser`,
`GetFriendAvatar`), передавайте таблицу такой формы. Обычно такие таблицы вы получаете из `GetLocalUser()`,
`GetFriends()`, списка участников лобби и т. д.

> **Совет:** предпочитайте `textId` при сохранении SteamID на диск или передаче по сети — большие 64-битные целые
> числа в некоторых контекстах могут терять точность, а строковая форма — никогда.

<a id="binary-data-as-lua-strings"></a>
### Бинарные данные как строки Lua

Везде, где API работает с **сырыми байтами** — файлы Steam Cloud, P2P-данные, чат лобби, голосовые данные, билеты
аутентификации, сырые пиксели RGBA — байты передаются в Lua и из Lua как **строки Lua**. Строки Lua бинарно-безопасны
(могут содержать `\0`), поэтому это происходит без потерь. Там, где API принимает данные для отправки/записи, вы также
можете **передать** массив байтов (таблицу Lua из целых чисел `0–255`); возвращаемые данные всегда являются строкой.

```lua
-- Запишем произвольные байты в облако и прочитаем их обратно:
Storefront.CloudWrite("save.dat", "any\0binary\0bytes")
local data, r = Storefront.CloudRead("save.dat")
if r == Storefront.Result.Ok then
    Print("Прочитано " .. #data .. " байт")
end
```

<a id="backend-availability-and-steam-only-calls"></a>
### Доступность бэкенда и Steam-специфичные вызовы

Каждая функция в `Storefront` — без исключений — проходит через интерфейс бэкенда плагина, а не напрямую в Steam.
Отличается лишь то, какую часть этого интерфейса реализует конкретный бэкенд:

- **Переносимое ядро** (достижения, статистика, таблицы лидеров, облако, друзья, Rich Presence, оверлей, лобби,
  P2P, DLC) обязательно для любого бэкенда. Если активного бэкенда нет вообще, эти функции возвращают безопасное
  значение по умолчанию (`NotInitialized`, `false`, `nil` или пустую таблицу).
- **Группы возможностей** (Мастерская, Input, Timeline, голос, билеты аутентификации, информация об устройстве,
  экранная клавиатура, информация о приложении, аватары, скриншоты) — опциональны. Бэкенд, который группу не
  реализует, возвращает те же безопасные значения по умолчанию, а там, где возвращается код результата, —
  `Unsupported`. Ничего не бросается и ничего не падает.

Спрашивайте, прежде чем ветвиться, вместо того чтобы предполагать Steam:

```lua
if Storefront.Supports(Storefront.Capability.Workshop) then
    ShowModBrowser()
end
```

[`Storefront.Supports`](#414-storefrontsupports) — штатный способ узнать, что умеет активный бэкенд. Сегодня Steam
— единственный бэкенд, который поставляется с плагином, и он сообщает о поддержке всех возможностей, кроме
`Timeline`: та дополнительно зависит от того, достаточно ли новый клиент Steam.

Всегда ставьте свою интеграцию в зависимость от доступности и входа в систему:

```lua
function OnCreate()
    if not Storefront.IsAvailable() then return end   -- не Steam-сборка / нет AppId
    if not Storefront.IsLoggedIn()  then return end   -- клиент Steam не выполнил вход
    Print("Привет, " .. Storefront.GetPersonaName())
end
```

<a id="4-session--identity"></a>
## 4. Сессия и идентификация

Информация только для чтения о текущей сессии Steam и локальном пользователе. Все эти функции синхронные.

### 4.1 Storefront.IsAvailable

```lua
Storefront.IsAvailable() -> bool
```

Возвращает `true`, если активен бэкенд storefront (плагин успешно инициализирован с действительным AppId и
вошедшим в систему пользователем). На платформах без Steam или когда AppId не настроен, возвращает `false`. Это первая
проверка, которую должна делать любая интеграция.

```lua
if not Storefront.IsAvailable() then
    Print("Работаем без Steam — пропускаем функции Steam")
    return
end
```

---

### 4.2 Storefront.GetBackend

```lua
Storefront.GetBackend() -> string
```

Возвращает имя активного бэкенда: `"Steam"`, когда Steam активен, иначе `"None"`.

```lua
Print("Бэкенд storefront: " .. Storefront.GetBackend())
```

---

### 4.3 Storefront.GetBackendId

```lua
Storefront.GetBackendId() -> int
```

Возвращает активный бэкенд в виде целого числа (см. [`Storefront.Backend`](#backend-enum)): `1` для Steam, `0` если бэкенда нет.
Перечисление резервирует идентификаторы и под бэкенды, которые у плагина могут появиться позже; сегодня
поставляется только `Steam`.

---

### 4.4 Storefront.IsInitialized

```lua
Storefront.IsInitialized() -> bool
```

Возвращает `true`, если активный бэкенд сообщает, что он инициализирован. На практике для бэкенда Steam это отслеживает
то же состояние, что и `IsAvailable()`.

---

### 4.5 Storefront.IsLoggedIn

```lua
Storefront.IsLoggedIn() -> bool
```

Возвращает `true`, если локальный пользователь вошёл в Steam. Почти каждая функция требует этого — большинство функций
возвращают `NotInitialized`, когда это `false`.

```lua
if Storefront.IsAvailable() and Storefront.IsLoggedIn() then
    -- безопасно использовать достижения, облако, друзей и т. д.
end
```

---

### 4.6 Storefront.GetAppId

```lua
Storefront.GetAppId() -> int
```

Возвращает Steam AppId, с которым инициализировался плагин (`0`, если активного бэкенда нет).

```lua
Print("AppId: " .. Storefront.GetAppId())
```

---

### 4.7 Storefront.GetLocalUser

```lua
Storefront.GetLocalUser() -> table | nil
```

Возвращает таблицу [`UserHandle`](#the-userhandle-table) локального игрока или `nil`, если он не вошёл в систему.

```lua
local me = Storefront.GetLocalUser()
if me then
    Print("Мой SteamID: " .. me.textId)
end
```

---

### 4.8 Storefront.GetPersonaName

```lua
Storefront.GetPersonaName() -> string
```

Возвращает отображаемое имя локального игрока в Steam (persona name). Пустая строка, если он не вошёл в систему.

```lua
Print("Добро пожаловать, " .. Storefront.GetPersonaName())
```

---

### 4.9 Storefront.GetCountryCode

```lua
Storefront.GetCountryCode() -> string
```

Возвращает двухбуквенный код страны ISO, который Steam определяет по IP пользователя (например, `"US"`, `"DE"`, `"UA"`).
Пустая строка, если недоступно. Полезно для региональных значений по умолчанию — **не** заменяет настоящую
гео-IP/юридическую проверку.

---

### 4.10 Storefront.GetLanguage

```lua
Storefront.GetLanguage() -> string
```

Возвращает язык, на котором у этого пользователя в Steam настроен запуск игры (строка языка API, например, `"english"`,
`"russian"`, `"german"`). Это отражает язык для конкретной игры, выбранный в клиенте Steam. Пустая строка, если
недоступно.

```lua
local lang = Storefront.GetLanguage()
if lang == "russian" then
    SetLanguage("ru")
end
```

---

### 4.11 Storefront.GetSteamUILanguage

```lua
Storefront.GetSteamUILanguage() -> string
```

Возвращает язык **самого интерфейса клиента Steam** (который может отличаться от языка для конкретной игры). Специфично для Steam.

---

### 4.12 Storefront.ResultName

```lua
Storefront.ResultName(code) -> string
```

Преобразует целочисленный код [`Result`](#result-enum) в его имя (например, `-2` → `"NotLoggedIn"`). Используйте его
для логирования и отладки — никогда не ветвите логику по *строке*; вместо этого сравнивайте числовой код с константами
`Storefront.Result.*`.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `code` | `int` | Код результата, возвращённый другой функцией |

```lua
local r = Storefront.CloudWrite("save.dat", data)
if r ~= Storefront.Result.Ok then
    Print("Запись в облако не удалась: " .. Storefront.ResultName(r))
end
```

---

### 4.13 Storefront.GetProductId

```lua
Storefront.GetProductId() -> string
```

Возвращает идентификатор продукта активного бэкенда **строкой** — то же значение, что и
[`Storefront.GetAppId()`](#46-storefrontgetappid) в случае Steam, где идентификатор числовой. Предпочитайте эту
функцию `GetAppId()` в коде, которому идентификатор нужен только для логирования или передачи: бэкенды, отличные
от Steam, обозначают продукт нечисловым идентификатором, и так этот код остаётся переносимым. Если активного
бэкенда нет, возвращает пустую строку.

```lua
Print("Продукт: " .. Storefront.GetProductId())
```

---

### 4.14 Storefront.Supports

```lua
Storefront.Supports(capability) -> bool
```

Сообщает, реализует ли активный бэкенд [группу возможностей](#capability-enum). Возвращает `false`, если активного
бэкенда нет, поэтому одна проверка закрывает сразу и «магазина нет вообще», и «этот магазин так не умеет».

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `capability` | `int` | Константа [`Storefront.Capability`](#capability-enum) |

```lua
if Storefront.Supports(Storefront.Capability.Voice) then
    EnableVoiceChatUI()
end

if not Storefront.Supports(Storefront.Capability.Timeline) then
    Print("Метки Game Recording на этом клиенте недоступны")
end
```

Вызов в неподдерживаемую группу всё равно безопасен — он вернёт нейтральное значение этой группы. `Supports` нужен
для того, чтобы прятать интерфейс и не делать лишнюю работу, а не вызывать и выбрасывать результат.

---

### 4.15 Storefront.CapabilityName

```lua
Storefront.CapabilityName(capability) -> string
```

Преобразует константу [`Storefront.Capability`](#capability-enum) в её имя (например, `12` → `"Workshop"`). Только
для логирования и отладки — ветвите логику по числовым константам, а не по строке.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `capability` | `int` | Константа [`Storefront.Capability`](#capability-enum) |

```lua
for _, cap in ipairs({ Storefront.Capability.Workshop, Storefront.Capability.Input }) do
    Print(Storefront.CapabilityName(cap) .. ": " .. tostring(Storefront.Supports(cap)))
end
```

<a id="5-achievements"></a>
## 5. Достижения

Достижения идентифицируются по их **API-имени** (id, который вы задаёте на партнёрском сайте Steamworks, например,
`ACH_WIN_ONE_GAME`), а не по отображаемому имени.

Метаданные достижений кешируются при инициализации плагина и обновляются, когда Steam доставляет обновлённую
статистику. Чтения (`GetAchievement`, `GetAllAchievements`) обслуживаются из этого кеша и являются синхронными; записи
уходят в Steam и сохраняются немедленно.

### 5.1 Storefront.UnlockAchievement

```lua
Storefront.UnlockAchievement(id) -> int
```

Разблокирует достижение и немедленно сохраняет его в Steam (который показывает всплывающее уведомление о разблокировке).
Идемпотентно — разблокировать уже разблокированное достижение безвредно.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя достижения |

**Возвращает:** код [`Result`](#result-enum) — `Ok` при успехе.

```lua
if enemiesKilled >= 100 then
    Storefront.UnlockAchievement("ACH_KILL_100")
end
```

---

### 5.2 Storefront.ClearAchievement

```lua
Storefront.ClearAchievement(id) -> int
```

Снова блокирует (сбрасывает) достижение и сохраняет изменение. В основном для разработки и тестирования.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя достижения |

**Возвращает:** код [`Result`](#result-enum).

---

### 5.3 Storefront.IndicateAchievementProgress

```lua
Storefront.IndicateAchievementProgress(id, current, max) -> int
```

Показывает всплывающее **уведомление о прогрессе** Steam (например, «37 / 100») для достижения, основанного на
прогрессе. Это **не** разблокирует достижение — когда соответствующая статистика достигнет своей цели, Steam
разблокирует его. Используйте это исключительно для того, чтобы показывать игроку прогресс на значимых вехах.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя достижения |
| `current` | `int` | Текущее значение прогресса |
| `max` | `int` | Целевое значение прогресса |

**Возвращает:** код [`Result`](#result-enum).

```lua
-- Каждые 10 убийств показываем прогресс к достижению «100 убийств»:
if kills % 10 == 0 and kills < 100 then
    Storefront.IndicateAchievementProgress("ACH_KILL_100", kills, 100)
end
```

---

### 5.4 Storefront.GetAchievement

```lua
Storefront.GetAchievement(id) -> table | nil
```

Возвращает метаданные одного достижения или `nil`, если id неизвестен.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя достижения |

**Возвращает:** таблицу [`Achievement`](#achievement-table):

| Поле | Тип | Описание |
|-------|------|-------------|
| `id` | `string` | API-имя |
| `displayName` | `string` | Локализованное отображаемое имя |
| `description` | `string` | Локализованное описание |
| `hidden` | `bool` | `true`, если достижение скрыто до разблокировки |
| `unlocked` | `bool` | Есть ли оно у локального пользователя |
| `progress` | `float` | Текущий прогресс (`0`, если здесь это не отслеживаемое по прогрессу достижение) |
| `progressMax` | `float` | Максимальное значение прогресса (`0`, если это не достижение по прогрессу) |
| `globalUnlockPercent` | `float` | Глобальный процент разблокировки среди всех игроков, или `-1`, если ещё недоступен |
| `unlockTime` | `int` | Unix-время (в секундах) разблокировки, или `0`, если заблокировано |
| `iconLocked` | `string` | Зарезервировано (пусто) — используйте [`GetAchievementIcon`](#162-storefrontgetachievementicon) |
| `iconUnlocked` | `string` | Зарезервировано (пусто) — используйте [`GetAchievementIcon`](#162-storefrontgetachievementicon) |

```lua
local a = Storefront.GetAchievement("ACH_WIN_ONE_GAME")
if a then
    Print(a.displayName .. " — " .. (a.unlocked and "разблокировано" or "заблокировано"))
    if a.globalUnlockPercent >= 0 then
        Print(string.format("%.1f%% игроков имеют это", a.globalUnlockPercent))
    end
end
```

> `globalUnlockPercent` равен `-1`, пока Steam не доставит глобальную статистику. Плагин запрашивает её при
> инициализации; вы также можете вызвать
> [`RequestGlobalAchievementPercentages`](#164-storefrontrequestglobalachievementpercentages) и прочитать значение
> через несколько кадров.

---

### 5.5 Storefront.GetAllAchievements

```lua
Storefront.GetAllAchievements() -> table
```

Возвращает массив с индексацией от 1 из таблиц [`Achievement`](#achievement-table) для каждого достижения, определённого
для приложения. Порядок не определён. Возвращает пустую таблицу, если пользователь не вошёл в систему или до заполнения
кеша.

```lua
for _, a in ipairs(Storefront.GetAllAchievements()) do
    Print(a.id .. ": " .. (a.unlocked and "✔" or "✘"))
end
```

<a id="6-stats"></a>
## 6. Статистика

**Статистика** Steam — это именованные числовые значения, хранящиеся для каждого пользователя (и при желании
агрегируемые глобально). Целочисленная и вещественная статистика — это разные типы; читайте статистику тем же типом,
которым вы её определили на партнёрском сайте.

> **Сохранение:** `SetStatInt` / `SetStatFloat` изменяют значение **локально**. Вызовите
> [`StoreStats`](#65-storefrontstorestats), чтобы выгрузить их в Steam. (Разблокировка/сброс достижения и
> `ResetAllStats` сбрасывают статистику за вас, но явные записи статистики — нет.)

### 6.1 Storefront.SetStatInt

```lua
Storefront.SetStatInt(id, value) -> int
```

Устанавливает целочисленную статистику локально.

> **Целочисленные статистики Steam 32-битные.** Lua даёт вам 64-битные целые, и всё, что выходит за пределы
> знакового 32-битного диапазона, обрезается по пути в Steam без всякой ошибки. Для значения, способного перевалить
> за ~2,1 миллиарда (суммарный урон, всего заработано валюты), используйте
> [`SetStatFloat`](#62-storefrontsetstatfloat) или разложите его на две статистики.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя статистики |
| `value` | `int` | Новое значение |

**Возвращает:** код [`Result`](#result-enum).

---

```lua
Storefront.SetStatFloat(id, value) -> int
```

### 6.7 Storefront.UpdateAvgRateStat

```lua
Storefront.UpdateAvgRateStat(id, countThisSession, sessionLength) -> int
```

Обновляет статистику **среднего темпа** («AVGRATE») — помощник Steam для значений вроде «среднее число очков в час».
Вы передаёте ей количество, накопленное за эту сессию, и длительность сессии (в той же единице времени, например,
секунды или часы), а Steam поддерживает скользящее среднее. Специфично для Steam.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `id` | `string` | API-имя статистики AVGRATE |
| `countThisSession` | `number` | Количество, накопленное за эту сессию |
| `sessionLength` | `number` | Длительность этой сессии (согласованная единица времени) |

**Возвращает:** код [`Result`](#result-enum). Затем вызовите `StoreStats()`, чтобы сохранить.

```lua
-- Игрок заработал `points` очков за `dtHours` часов игры:
Storefront.UpdateAvgRateStat("AvgPointsPerHour", points, dtHours)
Storefront.StoreStats()
```

### 6.9 Storefront.AreStatsReady

```lua
Storefront.AreStatsReady() -> bool
```

Возвращает `true`, как только Steam доставил в запущенный процесс статистику и достижения этого пользователя.
Специфично для Steam.

Это важно, потому что **статистика и достижения недоступны в тот же миг, когда инициализируется Steam** — клиент
получает их со своего бэкенда и передаёт чуть позже, обычно в течение первых кадров. Всё, что вы записываете до
этого момента, отклоняется: `SetStatInt`, `SetStatFloat` и `UnlockAchievement` возвращают
[`BackendError`](#result-enum), а `GetAllAchievements()` возвращает пустую таблицу. Плагин не повторяет попытку за
вас, поэтому достижение, разблокированное в самом первом `OnCreate` самого первого уровня, может тихо потеряться.

Защитите ранние записи или просто отложите их:

```lua
local pendingUnlocks = {}

function Unlock(id)
    if Storefront.IsAvailable() and Storefront.AreStatsReady() then
        Storefront.UnlockAchievement(id)
    else
        pendingUnlocks[#pendingUnlocks + 1] = id
    end
end

function OnUpdate(dt)
    if #pendingUnlocks > 0 and Storefront.IsAvailable() and Storefront.AreStatsReady() then
        for _, id in ipairs(pendingUnlocks) do Storefront.UnlockAchievement(id) end
        pendingUnlocks = {}
    end
end
```

Разблокировка в конце забега, на переходе между уровнями или из любого меню происходит уже далеко за пределами
этого окна — проверка нужна только для записей в первые кадры сессии.

<a id="7-leaderboards"></a>
## 7. Таблицы лидеров

Таблицы лидеров адресуются непрозрачным **хэндлом** (целым числом). Сначала получите хэндл с помощью
`FindOrCreateLeaderboard`, затем загружайте по нему очки и скачивайте записи. Все функции таблиц лидеров асинхронны.

### 7.1 Storefront.FindOrCreateLeaderboard

```lua
Storefront.FindOrCreateLeaderboard(name, sort, display, callback)
```

Находит таблицу лидеров по имени (создавая её, если она ещё не существует и настройки вашего приложения это позволяют),
затем доставляет её хэндл в колбэк.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `name` | `string` | Имя таблицы лидеров (как настроено на партнёрском сайте) |
| `sort` | `int` | Значение [`LeaderboardSort`](#leaderboardsort-enum) (`Ascending` / `Descending`) |
| `display` | `int` | Значение [`LeaderboardDisplay`](#leaderboarddisplay-enum) (`Numeric` / `TimeSeconds` / `TimeMilliSeconds`) |
| `callback` | `function(result, handle)` | `handle` — хэндл таблицы лидеров (целое); `0` при неудаче |

```lua
local boardHandle = nil
Storefront.FindOrCreateLeaderboard("HighScores",
    Storefront.LeaderboardSort.Descending,
    Storefront.LeaderboardDisplay.Numeric,
    function(r, handle)
        if r == Storefront.Result.Ok then
            boardHandle = handle
        end
    end)
```

> **Совет:** получите хэндл один раз (например, на старте уровня) и закешируйте его; используйте повторно для всех
> последующих загрузок и скачиваний.

---

### 7.2 Storefront.UploadLeaderboardScore

```lua
Storefront.UploadLeaderboardScore(handle, score, details, method, callback)
```

Загружает очки в таблицу лидеров.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `handle` | `int` | Хэндл таблицы лидеров из `FindOrCreateLeaderboard` |
| `score` | `int` | Отправляемый счёт. Steam хранит результаты таблиц лидеров как **знаковые 32-битные** целые, поэтому значение обязано лежать между `-2147483648` и `2147483647`. Счёт вне этого диапазона отклоняется с `InvalidArgument` и строкой в логе, а не переполняется молча — масштабируйте или ограничивайте его в игре заранее. |
| `details` | `table` | Необязательный массив целых чисел (индексация от 1), сохраняемый вместе со счётом (например, метаданные); передайте `{}`, если их нет |
| `method` | `int` | Значение [`LeaderboardUpload`](#leaderboardupload-enum) — `KeepBest` (заменять, только если лучше) или `ForceUpdate` (заменять всегда) |
| `callback` | `function(result)` | Доставляет код [`Result`](#result-enum) |

```lua
Storefront.UploadLeaderboardScore(boardHandle, finalScore, {},
    Storefront.LeaderboardUpload.KeepBest,
    function(r)
        Print("Загрузка: " .. Storefront.ResultName(r))
    end)
```

> **Массив деталей:** Steam хранит до **64** целочисленных деталей на запись. Они возвращаются дословно, когда вы
> скачиваете записи, — удобно для хранения таких вещей, как сид реплея, id персонажа или промежуточные времена.

---

### 7.3 Storefront.DownloadLeaderboardEntries

```lua
Storefront.DownloadLeaderboardEntries(handle, range, rangeStart, rangeEnd, callback)
```

Скачивает набор записей таблицы лидеров.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `handle` | `int` | Хэндл таблицы лидеров |
| `range` | `int` | Значение [`LeaderboardRange`](#leaderboardrange-enum) — `Global`, `AroundUser` или `Friends` |
| `rangeStart` | `int` | Начальный индекс (значение зависит от `range`, см. ниже) |
| `rangeEnd` | `int` | Конечный индекс |
| `callback` | `function(result, entries)` | `entries` — массив таблиц [`LeaderboardEntry`](#leaderboardentry-table) |

**Семантика диапазона:**

- **`Global`** — `rangeStart`/`rangeEnd` — абсолютные ранги (от 1). `(1, 10)` = топ-10.
- **`AroundUser`** — относительно ранга локального пользователя. `(-4, 5)` = 4 выше и 5 ниже (10 записей с игроком в
  центре).
- **`Friends`** — только друзья пользователя; диапазон игнорируется Steam (передайте `(0, 0)`).

Каждая запись [`LeaderboardEntry`](#leaderboardentry-table) содержит:

| Поле | Тип | Описание |
|-------|------|-------------|
| `user` | `table` | [`UserHandle`](#the-userhandle-table) владельца записи |
| `displayName` | `string` | Имя профиля владельца в Steam |
| `rank` | `int` | Глобальный ранг |
| `score` | `int` | Счёт |
| `details` | `table` | Массив (индексация от 1) загруженных целочисленных деталей |

```lua
-- Топ-10:
Storefront.DownloadLeaderboardEntries(boardHandle,
    Storefront.LeaderboardRange.Global, 1, 10,
    function(r, entries)
        if r ~= Storefront.Result.Ok then return end
        for _, e in ipairs(entries) do
            Print(e.rank .. ". " .. e.displayName .. " — " .. e.score)
        end
    end)

-- Записи вокруг игрока:
Storefront.DownloadLeaderboardEntries(boardHandle,
    Storefront.LeaderboardRange.AroundUser, -4, 5,
    function(r, entries) --[[ ... ]] end)
```

## 8. Steam Cloud

Steam Cloud (Remote Storage) хранит файлы каждого пользователя, которые синхронизируются между его машинами. Файлы
адресуются по имени; содержимое — сырые байты (строки Lua). Все облачные функции синхронны.

> **Включение облака:** Steam Cloud должен быть включён для вашего приложения на партнёрском сайте **и**
> пользователем. Проверяйте [`CloudIsEnabled`](#86-storefrontcloudisenabled), прежде чем полагаться на него. Записи
> всё равно успешно проходят локально и синхронизируются, когда облако включено.

### 8.1 Storefront.CloudWrite

```lua
Storefront.CloudWrite(name, data) -> int
```

Записывает файл в облако, перезаписывая любой существующий файл с тем же именем.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `name` | `string` | Имя файла (например, `"slot1.sav"`) |
| `data` | `string` \| `table` | Сырые байты — бинарно-безопасная строка Lua или массив целых чисел `0–255` (индексация от 1) |

**Возвращает:** код [`Result`](#result-enum). `QuotaExceeded`, если файл больше ~2 ГБ.

```lua
Storefront.CloudWrite("slot1.sav", SaveStateToString())
```

---

### 8.2 Storefront.CloudRead

```lua
Storefront.CloudRead(name) -> (string | nil, int)
```

Читает облачный файл. Возвращает содержимое файла как бинарно-безопасную строку (или `nil`) и код
[`Result`](#result-enum) (`NotFound`, если файл не существует).

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `name` | `string` | Имя файла |

```lua
local data, r = Storefront.CloudRead("slot1.sav")
if r == Storefront.Result.Ok then
    LoadStateFromString(data)
elseif r == Storefront.Result.NotFound then
    Print("Облачного сохранения ещё нет")
end
```

---

```lua
Storefront.CloudDelete(name) -> int
```

Удаляет облачный файл. Возвращает `NotFound`, если он не существует.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `name` | `string` | Имя файла |

**Возвращает:** код [`Result`](#result-enum).

```lua
Storefront.CloudList() -> table
```

Возвращает массив (индексация от 1) таблиц [`CloudFile`](#cloudfile-table), описывающих каждый файл, который сейчас

Каждая таблица [`CloudFile`](#cloudfile-table):

| Поле | Тип | Описание |

### 8.5 Storefront.CloudQuotaTotal / CloudQuotaAvailable

```lua
Storefront.CloudQuotaTotal()     -> int   -- всего выделено байт

```

```lua
local used = Storefront.CloudQuotaTotal() - Storefront.CloudQuotaAvailable()
```

### 8.6 Storefront.CloudIsEnabled

```lua
Storefront.CloudIsEnabled() -> bool
```

аккаунта (настройка пользователя).

```lua
if Storefront.CloudIsEnabled() then
    Storefront.CloudWrite("slot1.sav", data)
else
    SaveLocally(data)   -- запасной вариант — локальный диск
end
```

## 9. Друзья, Rich Presence и оверлей

### 9.1 Storefront.GetFriends

```lua
Storefront.GetFriends() -> table
```

Возвращает массив (индексация от 1) таблиц [`Friend`](#friend-table) для непосредственных друзей локального
пользователя.

Каждая таблица [`Friend`](#friend-table):

## 10. Лобби (матчмейкинг)

Лобби — это примитив матчмейкинга Steam: общая комната с серверным листингом, у которой есть владелец, участники,
метаданные ключ/значение и канал чата. Лобби идентифицируются целочисленным **id лобби**.

Создание, присоединение и поиск асинхронны; всё остальное синхронно. Чтобы получать события чата и изменения состава,
зарегистрируйте [`OnLobbyChat`](#192-storefrontonlobbychat) и
[`OnLobbyMemberChanged`](#193-storefrontonlobbymemberchanged).

### 10.1 Storefront.CreateLobby

```lua

```

Создаёт новое лобби, владельцем которого является локальный пользователь.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `type` | `int` | Значение [`LobbyType`](#lobbytype-enum) (`Private` / `FriendsOnly` / `Public` / `Invisible`) |
| `maxMembers` | `int` | Максимум участников (включая владельца) |


`filter` — это таблица со следующими необязательными полями:

| Поле | Тип | Описание |
|-------|------|-------------|
| `stringEquals` | `table` | Карта `string → string`; только лобби, чьи метаданные совпадают со всеми записями |
| `intEquals` | `table` | Карта `string → int`; фильтры по равенству числовых метаданных |

```lua
Storefront.SearchLobbies({

    minSlotsAvailable = 1,
    resultLimit       = 20,
}, function(r, lobbies)
    if r ~= Storefront.Result.Ok then return end
```

<a id="11-p2p-networking"></a>
## 11. P2P-сеть

Одноранговый обмен сообщениями построен на сети Steam с ретрансляторами (`SteamNetworkingMessages`), поэтому он
работает через NAT и брандмауэры без необходимости поднимать сервер. Сообщения адресуются пользователю, помечаются
**каналом** и отправляются с **типом отправки** (надёжность). Входящие сессии **принимаются автоматически**.

Есть два способа получать сообщения — выберите один:

- **Опрос:** вызывайте [`ReceiveP2P`](#112-storefrontreceivep2p) каждый кадр, чтобы вытягивать сообщения из очереди.
- **Колбэк:** зарегистрируйте [`OnP2PMessage`](#191-storefrontonp2pmessage). **Если обработчик зарегистрирован,
  сообщения доставляются ему и *не* ставятся в очередь для опроса.**

Принимаются только каналы `0–3` (значения [`P2PChannel`](#p2pchannel-enum)).

### 11.1 Storefront.SendP2P

```lua
Storefront.SendP2P(user, data, channel, sendType) -> int
```

Отправляет сообщение другому пользователю.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `user` | `table` | Целевой [`UserHandle`](#the-userhandle-table) |
| `data` | `string` \| `table` | Байты данных — строка или массив `0–255` |
| `channel` | `int` | Значение [`P2PChannel`](#p2pchannel-enum) (`Default` / `GameState` / `Voice` / `FileTransfer`) |
| `sendType` | `int` | Значение [`P2PSendType`](#p2psendtype-enum) (надёжность — см. ниже) |

**Возвращает:** код [`Result`](#result-enum) — `Ok`, `NetworkFailure` (нет соединения) или `BackendError`.

**Типы отправки:**

- **`Unreliable`** — может быть потеряно или прийти не по порядку; минимальная задержка. Подходит для частых снимков
  состояния.
- **`UnreliableNoDelay`** — ненадёжно и никогда не буферизуется/не задерживается алгоритмом Нейгла; минимально
  возможная задержка.
- **`Reliable`** — гарантированная, упорядоченная доставка (как TCP). Подходит для команд, чата, важных событий.
- **`ReliableWithBuffering`** — надёжно, но позволяет сетевому слою объединять мелкие отправки ради пропускной
  способности.

```lua
local payload = string.pack("<fff", x, y, angle)   -- упаковываем небольшой снимок состояния
Storefront.SendP2P(peer, payload,
    Storefront.P2PChannel.GameState,
    Storefront.P2PSendType.Unreliable)
```

---

### 11.2 Storefront.ReceiveP2P

```lua
Storefront.ReceiveP2P() -> table | nil
```

Извлекает следующее входящее сообщение из очереди или `nil`, если очередь пуста. Опустошайте её в цикле каждый кадр.
**Не действует, если вы зарегистрировали `OnP2PMessage`** (такие сообщения идут в колбэк).

**Возвращает:** таблицу [`P2PMessage`](#p2pmessage-table):

| Поле | Тип | Описание |
|-------|------|-------------|
| `sender` | `table` | [`UserHandle`](#the-userhandle-table) отправителя |
| `channel` | `int` | [`P2PChannel`](#p2pchannel-enum), на который пришло сообщение |
| `payload` | `string` | Сырые байты |

```lua
function OnUpdate(dt)
    Storefront.Tick()
    while true do
        local msg = Storefront.ReceiveP2P()
        if not msg then break end
        HandlePacket(msg.sender, msg.channel, msg.payload)
    end
end
```

> Входящая очередь ограничена (самые старые сообщения отбрасываются сверх ~4096 ожидающих). Опустошайте её каждый кадр.

## 12. Голосовой чат

Захватывайте локальный микрофон через голосовую систему Steam (которая берёт на себя захват и встроенный кодек),
сами передавайте сжатые байты (например, через [P2P](#11-p2p-networking)) и декодируйте полученные байты в PCM для
воспроизведения. Все голосовые функции специфичны для Steam.

### 12.1 Storefront.StartVoiceRecording / StopVoiceRecording

```lua
Storefront.StartVoiceRecording() -> bool
Storefront.StopVoiceRecording()  -> bool
```

Начинает / завершает захват микрофона. Возвращают `true`, если вызов был выполнен. Во время записи каждый кадр
опрашивайте [`GetVoice`](#122-storefrontgetvoice), чтобы получать сжатый звук.

```lua
function OnPushToTalkDown() Storefront.StartVoiceRecording() end
function OnPushToTalkUp()   Storefront.StopVoiceRecording()  end
```

---

### 12.2 Storefront.GetVoice

```lua
Storefront.GetVoice() -> (int, string | nil)
```

Вытягивает следующий фрагмент **сжатого** захваченного голоса. Возвращает код [`Result`](#result-enum) и сжатые байты
(или `nil`, когда пока ничего нет). Опрашивайте её каждый кадр во время записи.

- `Ok` со строкой → есть сжатый звук для отправки.
- `Ok` с `nil` → сейчас данных нет (запись идёт, но тишина).
- `Pending` → захват инициализируется; попробуйте снова в следующем кадре.

```lua
function OnUpdate(dt)
    Storefront.Tick()
    local r, voice = Storefront.GetVoice()
    if r == Storefront.Result.Ok and voice then
        -- рассылаем сжатый голос пирам по каналу Voice
        for _, peer in ipairs(peers) do
            Storefront.SendP2P(peer, voice,
                Storefront.P2PChannel.Voice,
                Storefront.P2PSendType.UnreliableNoDelay)
        end
    end
end
```

---

### 12.3 Storefront.DecompressVoice

```lua
Storefront.DecompressVoice(compressed) -> (int, string | nil, int)
```

Декодирует сжатые голосовые байты (полученные от пира) в сырой **16-битный знаковый PCM** (моно). Возвращает код
[`Result`](#result-enum), байты PCM (или `nil`) и **частоту дискретизации** в Гц.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `compressed` | `string` | Сжатые голосовые байты, полученные из `GetVoice` пира |

```lua
-- Когда приходит P2P-сообщение по каналу Voice:
local r, pcm, sampleRate = Storefront.DecompressVoice(msg.payload)
if r == Storefront.Result.Ok and pcm then
    -- `pcm` — это 16-битное знаковое моно с частотой `sampleRate` Гц — передайте его в воспроизведение звука
    PlayPCM(pcm, sampleRate)
end
```

> Формат PCM: знаковый 16-битный little-endian, моно. Каждый сэмпл занимает 2 байта, так что число сэмплов равно `#pcm / 2`.

## 14. Мастерская (UGC)

Мастерская Steam позволяет игрокам публиковать, просматривать, подписываться на пользовательский контент (моды, карты,
скины) и скачивать его. Все функции Мастерской находятся под **`Storefront.Workshop.*`** и специфичны для Steam.

Элементы идентифицируются 64-битным **id элемента** (id опубликованного файла). Steam скачивает элементы, на которые
оформлена подписка, в отдельную папку для каждого элемента; найти её можно через
[`GetInstallInfo`](#144-storefrontworkshopgetinstallinfo).

> **Жизненный цикл опубликованного элемента:** `CreateItem` → задать поля и загрузить через таблицу `args` → Steam
> назначает id элемента → позже `UpdateItem` для отправки изменений. Игроки используют `Subscribe` / `Download` /
> `Unsubscribe`.

### 14.1 Storefront.Workshop.GetSubscribed

```lua
Storefront.Workshop.GetSubscribed(includeDisabled) -> table
```

`includeDisabled` необязателен и по умолчанию `false`; передайте `true`, чтобы получить также элементы, выключенные
игроком в интерфейсе самого Steam (см. [`SetItemsDisabledLocally`](#1415-storefrontworkshopsetitemsdisabledlocally)).

> Здесь заполняется только **локальное** состояние — `installed`, `installFolder`, `needsUpdate`,
> `disabledLocally` и т. п. `title`, `description`, `tags` и `metadata` приходят с бэкенда Steam: получите их через
> [`QueryItemsByIds`](#1411-storefrontworkshopqueryitemsbyids).

Возвращает массив (индексация от 1) таблиц [`WorkshopItem`](#workshopitem-table) для каждого элемента, на который
подписан пользователь, с заполненным локальным состоянием (установлено / скачивается / требуется обновление).

```lua
for _, item in ipairs(Storefront.Workshop.GetSubscribed()) do
    if item.installed then
        MountMod(item.installFolder)
    end
end
```

---

### 14.2 Storefront.Workshop.GetItemInfo

```lua
Storefront.Workshop.GetItemInfo(itemId) -> table | nil
```

Возвращает таблицу [`WorkshopItem`](#workshopitem-table) с **локальным** состоянием одного элемента (подписка,
установка, прогресс скачивания, папка установки) или `nil`, если Мастерская недоступна. Учтите, что поля, описывающие
опубликованный листинг (заголовок, описание, голоса, теги), заполняются только через
[`QueryUserItems`](#146-storefrontworkshopqueryuseritems) — `GetItemInfo` возвращает локально известное состояние.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `itemId` | `int` | Id элемента Мастерской |

```lua
local info = Storefront.Workshop.GetItemInfo(itemId)
if info and info.needsUpdate then
    Storefront.Workshop.Download(itemId, true, function(r) end)
end
```

---

### 14.3 Storefront.Workshop.GetItemState

```lua
Storefront.Workshop.GetItemState(itemId) -> int
```

Возвращает сырую **битовую маску** состояния элемента от Steam. В большинстве случаев предпочтительнее использовать
декодированные булевы поля таблицы [`WorkshopItem`](#workshopitem-table) (`subscribed`, `installed`, `needsUpdate`,
`downloading`) из `GetItemInfo`/`GetSubscribed`. Биты маски: `1` = подписан, `2` = устаревшее (legacy), `4` =
установлено, `8` = требуется обновление, `16` = скачивается, `32` = скачивание ожидается.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `itemId` | `int` | Id элемента Мастерской |

```lua
local state = Storefront.Workshop.GetItemState(itemId)
local installed = (state & 4) ~= 0
```

### 14.7 Storefront.Workshop.CreateItem

```lua
Storefront.Workshop.CreateItem(args, callback)
```

Создаёт **новый** элемент Мастерской и загружает его начальное содержимое за один шаг. Steam назначает новый id
элемента, затем плагин применяет ваши поля и отправляет загрузку.

`args` — это таблица со следующими полями (все необязательны, если не указано иное):

| Поле | Тип | Описание |
|-------|------|-------------|
| `title` | `string` | Заголовок элемента |
| `description` | `string` | Описание элемента |
| `contentFolder` | `string` | Абсолютный путь к папке, содержимое которой становится полезной нагрузкой элемента |
| `previewImagePath` | `string` | Абсолютный путь к изображению превью (JPG/PNG, ≤ 1 МБ) |
| `visibility` | `int` | Значение [`WorkshopVisibility`](#workshopvisibility-enum) (по умолчанию `Public`; опустите поле, чтобы при обновлении не трогать текущую видимость) |
| `tags` | `table` | Массив строк-тегов (индексация от 1) |
| `metadata` | `string` | Метаданные разработчика, до 10 000 символов — ваш машиночитаемый блоб (версия формата мода, входной скрипт, требуемый API движка), невидимый игрокам и возвращаемый [`QueryItemsByIds`](#1411-storefrontworkshopqueryitemsbyids) |
| `changeNote` | `string` | Заметка для первой загрузки (по умолчанию `"Initial upload"`) |

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `args` | `table` | Поля выше |
| `callback` | `function(result, itemId, needsLegalAgreement)` | При успехе `itemId` — id нового элемента; `needsLegalAgreement` равно `true`, когда элемент останется скрытым, пока автор не примет соглашение Мастерской |

```lua
Storefront.Workshop.CreateItem({
    title            = "My Custom Map",
    description      = "A spooky forest level.",
    contentFolder    = ModExportPath() .. "/MyMap",
    previewImagePath = ModExportPath() .. "/MyMap/preview.png",
    visibility       = Storefront.WorkshopVisibility.Public,
    tags             = { "Map", "Singleplayer" },
    metadata         = '{"modFormat":2,"entry":"main.lua"}',
}, function(r, itemId, needsLegalAgreement)
    if r ~= Storefront.Result.Ok then
        Print("Публикация не удалась: " .. Storefront.ResultName(r))
        return
    end
    Print("Опубликован элемент " .. itemId)
    SetString("my_workshop_item", tostring(itemId))

    if needsLegalAgreement then
        ShowDialog("Примите соглашение Мастерской Steam, чтобы элемент стал видимым.")
        Storefront.Workshop.OpenLegalAgreement()
    end
end)
```

> **Всегда реагируйте на `needsLegalAgreement`.** Пока автор его не примет, элемент невидим вообще для всех —
> включая самого автора — и нигде никакой ошибки не будет. См.
> [`OpenLegalAgreement`](#1413-storefrontworkshopopenlegalagreement).

> **Теги должны быть заранее заведены в настройках Мастерской вашего приложения** на партнёрском сайте Steamworks.
> Steam отклоняет неизвестные ему теги, и загрузка падает с общей ошибкой бэкенда.

### 14.8 Storefront.Workshop.UpdateItem

```lua
Storefront.Workshop.UpdateItem(itemId, args, callback)
```

Обновляет существующий элемент, которым вы владеете. Изменяется только то, что вы передали: опущенное или пустое
поле оставляет свойство как было, а полное отсутствие `visibility` оставляет текущую видимость элемента нетронутой.

`args` принимает те же поля, что и [`CreateItem`](#147-storefrontworkshopcreateitem), плюс:

| Поле | Тип | Описание |
|-------|------|-------------|
| `changeNote` | `string` | Заметка об изменениях, описывающая это обновление (показывается в истории изменений элемента) |

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `itemId` | `int` | Обновляемый элемент |
| `args` | `table` | Изменяемые поля |
| `callback` | `function(result, itemId, needsLegalAgreement)` | При успехе возвращает id элемента; `needsLegalAgreement` равно `true`, когда элемент останется скрытым, пока автор не примет соглашение Мастерской |

```lua
Storefront.Workshop.UpdateItem(itemId, {
    description   = "Updated for v1.2 — fixed spawn points.",
    contentFolder = ModExportPath() .. "/MyMap",
    changeNote    = "Bugfix patch",
    metadata      = '{"modFormat":2,"entry":"main.lua"}',
}, function(r, id, needsLegalAgreement)
    Print("Обновление: " .. Storefront.ResultName(r))
    if needsLegalAgreement then Storefront.Workshop.OpenLegalAgreement() end
end)
```

Пока это выполняется, опрашивайте [`GetUpdateProgress`](#1414-storefrontworkshopgetupdateprogress), чтобы показать

### 14.11 Storefront.Workshop.QueryItemsByIds

```lua
Storefront.Workshop.QueryItemsByIds(itemIds, callback)
```

Получает **полные данные** — заголовок, описание, теги, метаданные, счётчики голосов, URL превью — для конкретного
списка элементов. Асинхронно.

Это дополнение к [`GetSubscribed`](#141-storefrontworkshopgetsubscribed), который сообщает только локальное
состояние и оставляет `title` и `description` пустыми. Сначала список подписок, потом детали:

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `itemIds` | `table` | Массив id элементов Мастерской; **не более 50** за вызов |

```lua
local subscribed = Storefront.Workshop.GetSubscribed()

for _, item in ipairs(subscribed) do ids[#ids + 1] = item.itemId end

Storefront.Workshop.QueryItemsByIds(ids, function(r, items)

    end
end)
```

Передача больше 50 id возвращает `InvalidArgument`, не обращаясь к Steam; разбивайте список на страницы сами, если

### 14.13 Storefront.Workshop.OpenLegalAgreement

```lua
Storefront.Workshop.OpenLegalAgreement() -> int
```

Открывает юридическое соглашение Мастерской Steam в оверлее.

**Вы обязаны вызвать это, когда публикация сообщает `needsLegalAgreement`.** Пока автор не примет соглашение,
только что загруженный им элемент существует, но **невидим вообще для всех, включая его самого** — без ошибки, без
предупреждения, он просто никогда не появляется. Это самое частое обращение в поддержку вида «мод загрузился, но
его никто не видит».

```lua
Storefront.Workshop.CreateItem(args, function(r, itemId, needsLegalAgreement)
    if r ~= Storefront.Result.Ok then return end
    if needsLegalAgreement then
        ShowDialog("Остался шаг: примите соглашение Мастерской Steam, чтобы элемент стал видимым.")
        Storefront.Workshop.OpenLegalAgreement()
    end
end)
```

### 14.14 Storefront.Workshop.GetUpdateProgress

```lua
Storefront.Workshop.GetUpdateProgress() -> table
```

Прогресс текущей загрузки. Опрашивайте каждый кадр, пока выполняется `CreateItem` / `UpdateItem`, чтобы двигать
полосу прогресса — выгрузка мода единственная операция Мастерской, достаточно долгая, чтобы тишина выглядела как
зависание.

| Поле | Тип | Описание |
|-------|------|-------------|
| `status` | `int` | Значение [`WorkshopUpdateStatus`](#workshopupdatestatus-enum); `Invalid`, когда ничего не выгружается |
| `bytesProcessed` | `int` | Обработано байт |
| `bytesTotal` | `int` | Всего байт для текущего этапа; `0`, пока Steam не знает |

```lua
function OnUpdate(dt)
    local p = Storefront.Workshop.GetUpdateProgress()
    if p.status ~= Storefront.WorkshopUpdateStatus.Invalid and p.bytesTotal > 0 then
        SetProgressBar(p.bytesProcessed / p.bytesTotal)
    end
end
```

### 14.15 Storefront.Workshop.SetItemsDisabledLocally

```lua
Storefront.Workshop.SetItemsDisabledLocally(itemIds, disabled) -> int
```

Помечает подписанные элементы как локально выключенные (или включает обратно) **в учёте самого Steam**. Выключенный
элемент остаётся в подписках и на диске, но пропадает из `GetSubscribed()`, если о нём не попросить, и сообщает
`disabledLocally = true`.

Используйте это, чтобы ваши внутриигровые переключатели модов опирались на состояние Steam, а не на собственный
список: игрок видит то же вкл/выкл в клиенте Steam, и это переживает переустановку игры.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `itemIds` | `table` | Массив id элементов Мастерской |
| `disabled` | `bool` | `true` — выключить, `false` — включить обратно |

```lua
Storefront.Workshop.SetItemsDisabledLocally({ itemId }, true)
local all = Storefront.Workshop.GetSubscribed(true)   -- передайте true, чтобы всё равно видеть выключенные
```

### 14.16 Storefront.Workshop.SetSubscriptionsLoadOrder

```lua
Storefront.Workshop.SetSubscriptionsLoadOrder(itemIds) -> int
```

Сохраняет порядок, в котором должны загружаться подписанные элементы, чтобы перестановка, сделанная игроком в вашем
меню модов, запомнилась Steam и одинаково отображалась в клиенте Steam. Передавайте **полный** упорядоченный список.

```lua
Storefront.Workshop.SetSubscriptionsLoadOrder({ topMod, middleMod, bottomMod })
```

Учтите, что собственная загрузка модов движком упорядочивается по `LoadOrder` в каждом `mod.json`; этот вызов
записывает предпочтительный порядок игрока на стороне Steam, а согласовать одно с другим — задача вашего меню модов.

### 14.17 Storefront.Workshop.MarkDownloadedItemAsUnused

```lua
Storefront.Workshop.MarkDownloadedItemAsUnused(itemId) -> int
```

Сообщает Steam, что ваша игра закончила работу с содержимым элемента и его можно вытеснить при освобождении места

### 14.18 Превращение элементов Мастерской в моды движка

API Мастерской говорит вам, **где** установлен подписанный элемент; система модов движка — это то, что его реально
**запускает**. Их соединяет один вызов: `Mods.AddSearchPath()` регистрирует произвольную директорию как место для
поиска модов, так что папка Мастерской становится модом без копирования хотя бы одного файла.

Steam устанавливает каждый подписанный элемент в собственную папку внутри
`steamapps/workshop/content/<appid>/<itemid>/`, и `item.installFolder` — это тот самый путь. Передайте эти папки
системе модов и пересканируйте:

```lua
function MountWorkshopMods()
    if not Storefront.IsAvailable() then return end

    Mods.ClearSearchPaths()

    for _, item in ipairs(Storefront.Workshop.GetSubscribed()) do
        if item.installed and not item.needsUpdate and item.installFolder ~= "" then
            Mods.AddSearchPath(item.installFolder)
        end
    end

    Mods.Refresh()
end
```

Контракт для элемента Мастерской в форме мода — это просто собственный контракт модов движка: загруженная **папка
контента** и есть папка мода:

```
MyWorkshopMod/          <- папка, которую вы передаёте в Workshop.CreateItem как contentFolder
├── mod.json            <- Name, Version, Author, EntryScript, LoadOrder, Dependencies
├── main.lua            <- EntryScript; получает MOD_NAME / MOD_VERSION / MOD_DIR и ModRequire()
└── ...                 <- всё остальное, что мод загружает через MOD_DIR
```

Практические замечания по конвейеру модов на базе Мастерской:

- **Пути поиска действуют в пределах сессии.** Они нигде не сохраняются; регистрируйте их при каждом запуске, до
  сканирования. Сначала вызывайте `Mods.ClearSearchPaths()`, чтобы элементы, от которых игрок только что отписался,
  выпали из списка.
- **Вновь обнаруженные моды по умолчанию выключены** — ровно как любой мод, которого нет в `Config/Mods.json`.
  Подписка не равна включению: вызывайте `Mods.SetEnabled(name, true)` для тех, что игрок включает. Это загружает
  мод немедленно, пока сцена запущена, и сохраняет выбор.
- **Имена должны быть уникальными.** Элемент Мастерской, у которого `Name` в `mod.json` совпадает с уже найденным
  модом из `Mods/`, пропускается с предупреждением. Попросите мододелов использовать префиксы.
- **Подключайте до того, как моды понадобятся.** `Mods.Refresh()` выгружает и загружает всё заново, поэтому
  вызывайте его из раннего стартового уровня (загрузочного или главного меню), а не посреди геймплея.
- **Учитывайте состояние элемента.** Пропускайте элементы, у которых `installed` равно `false` или `needsUpdate`
  равно `true`, — Steam ещё их скачивает. Используйте
  [`Storefront.Workshop.Download`](#149-storefrontworkshopdownload), чтобы поднять приоритет, и подключите элемент
  в одном из следующих кадров, когда `GetItemInfo(itemId).installed` станет `true`.
- **Проставляйте теги элементам Мастерской** (`tags` в `CreateItem` / `UpdateItem`), чтобы на странице Мастерской
  можно было фильтровать виды модов, и сначала заведите те же теги в настройках приложения в Steamworks — Steam
  отклоняет неизвестные ему теги.

<a id="15-steam-input--steam-deck"></a>
## 15. Steam Input и Steam Deck

Steam Input даёт вам единый, **основанный на действиях** API контроллеров Steam: вы определяете *действия* (например,
`"Jump"` или `"Move"`) и *наборы действий* в манифесте, а Steam сопоставляет их с тем устройством, которое использует
игрок, — Xbox, PlayStation, Switch Pro, Steam Controller или встроенное управление Steam Deck — включая собственные
пользовательские привязки игрока. Затем вы спрашиваете «нажато ли действие Jump?» вместо опроса сырых кнопок. Все
функции находятся под **`Storefront.Input.*`** и специфичны для Steam.

> **Автоматическая инициализация:** плагин уже вызывает `Init` Steam Input при запуске и `RunFrame` каждый тик,
> поэтому в большинстве случаев вы можете пропустить `Input.Init` / `Input.RunFrame` и сразу перейти к чтению
> контроллеров и действий. Вызывайте `Input.Init(manifestPath)`, только если вам нужно указать Steam конкретный
> манифест действий во время выполнения.

**Хэндлы:** контроллеры, наборы действий, слои наборов действий и действия — всё это адресуется целочисленными
**хэндлами**, которые вы получаете по имени. Получайте их один раз и кешируйте.

### 15.1 Storefront.Input.Init

```lua
Storefront.Input.Init(manifestPath?) -> bool
```

Гарантирует, что Steam Input инициализирован, при желании задавая абсолютный путь к вашему манифесту действий (файлу
`.vdf`, описывающему ваши действия, наборы действий и привязки по умолчанию). Возвращает `true`, если Steam Input готов.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `manifestPath` | `string` | *(необязательно)* Абсолютный путь к файлу манифеста действий |

```lua
Storefront.Input.Init("C:/Game/steam_input_manifest.vdf")
```

### 15.2 Storefront.Input.Shutdown / RunFrame

```lua

Storefront.Input.RunFrame()
```

`Shutdown` освобождает Steam Input; `RunFrame` прокачивает его один раз. Оба необязательны — плагин управляет
жизненным циклом Steam Input за вас. Вызывайте `RunFrame` вручную, только если вы отключили автоматический тик.

### 15.4 Storefront.Input.GetControllers

```lua
Storefront.Input.GetControllers() -> table
```

Возвращает массив (индексация от 1) таблиц [`Controller`](#controller-table) для каждого подключённого контроллера,

Каждая таблица [`Controller`](#controller-table):

| Поле | Тип | Описание |
|-------|------|-------------|
| `handle` | `int` | Хэндл контроллера (передаётся в другие функции `Input.*`) |

```lua
for _, c in ipairs(Storefront.Input.GetControllers()) do
```

### 15.6 Наборы действий и слои

```lua
Storefront.Input.GetActionSetHandle(name)               -> int
Storefront.Input.ActivateActionSet(handle, actionSet)
Storefront.Input.GetCurrentActionSet(handle)            -> int
Storefront.Input.ActivateActionSetLayer(handle, layer)
Storefront.Input.DeactivateActionSetLayer(handle, layer)
Storefront.Input.DeactivateAllActionSetLayers(handle)
```

**Набор действий** — это именованная группа привязок (например, `"InGameControls"`, `"MenuControls"`). Переключайте
активный набор при смене контекста (геймплей ↔ меню ↔ транспорт). **Слои** накладывают временные переопределения
привязок поверх набора (например, слой `"Scoped"` во время прицеливания).

| Функция | Описание |
|----------|-------------|
| `GetActionSetHandle(name)` | Получить хэндл набора действий по его имени в манифесте |
| `ActivateActionSet(handle, actionSet)` | Сделать `actionSet` активным набором контроллера |
| `GetCurrentActionSet(handle)` | Текущий активный хэндл набора действий контроллера |
| `ActivateActionSetLayer(handle, layer)` | Добавить слой набора действий |
| `DeactivateActionSetLayer(handle, layer)` | Убрать конкретный слой |
| `DeactivateAllActionSetLayers(handle)` | Убрать все слои |

```lua
local inGame = Storefront.Input.GetActionSetHandle("InGameControls")
for _, c in ipairs(Storefront.Input.GetControllers()) do
    Storefront.Input.ActivateActionSet(c.handle, inGame)
end
```

### 15.7 Цифровые действия

```lua
Storefront.Input.GetDigitalActionHandle(name)          -> int
Storefront.Input.GetDigitalActionData(handle, action)  -> table
```

**Цифровое действие** — это действие вкл/выкл (Jump, Fire, Interact). Получите хэндл один раз по имени, затем читайте
его состояние каждый кадр для конкретного контроллера.

`GetDigitalActionData` возвращает таблицу:

| Поле | Тип | Описание |
|-------|------|-------------|
| `state` | `bool` | `true`, пока действие нажато |
| `active` | `bool` | `true`, если действие привязано/доступно в текущем наборе действий |

```lua
local jump = Storefront.Input.GetDigitalActionHandle("Jump")

function OnUpdate(dt)
    Storefront.Tick()
    for _, c in ipairs(Storefront.Input.GetControllers()) do
        local d = Storefront.Input.GetDigitalActionData(c.handle, jump)
        if d.active and d.state then
            DoJump()
        end
    end
end
```

### 15.8 Аналоговые действия

```lua
Storefront.Input.GetAnalogActionHandle(name)          -> int
Storefront.Input.GetAnalogActionData(handle, action)  -> table
Storefront.Input.StopAnalogActionMomentum(handle, action)
```

**Аналоговое действие** — это действие с 1 или 2 осями (Move, Look, Throttle). `GetAnalogActionData` возвращает:

| Поле | Тип | Описание |
|-------|------|-------------|
| `x` | `float` | Горизонтальная ось (обычно `-1`…`1`) |
| `y` | `float` | Вертикальная ось (обычно `-1`…`1`) |
| `mode` | `int` | Режим источника (джойстик, трекпад, мышь, …), как сообщает Steam |
| `active` | `bool` | Привязано/активно ли действие в данный момент |

`StopAnalogActionMomentum` отменяет остаточную инерцию «броска» трекпада для действия.

```lua
local move = Storefront.Input.GetAnalogActionHandle("Move")
local m = Storefront.Input.GetAnalogActionData(controller, move)
if m.active then
    MovePlayer(m.x, m.y)
end
```

### 15.9 Источники действий и глифы

> Доступны два вида глифов: `GetGlyphSVGForActionOrigin(origin)` возвращает **путь к SVG-файлу**, а
> `GetGlyphPNGForActionOrigin(origin, size)` — **путь к PNG-файлу** одного из трёх фиксированных размеров. Оба
> возвращают путь в файловой системе, а не байты изображения — загружайте его обычным конвейером текстур. Берите
> PNG, если ваш рендерер интерфейса не растеризует SVG по-настоящему.
>
> ```lua
> local png = Storefront.Input.GetGlyphPNGForActionOrigin(origin, Storefront.GlyphSize.Medium)
> if png ~= "" then ShowButtonHint(png) end
> ```
>
> `size` необязателен и по умолчанию равен `Medium`; см. [`GlyphSize`](#glyphsize-enum).

```lua
Storefront.Input.GetDigitalActionOrigins(handle, actionSet, action) -> table
Storefront.Input.GetAnalogActionOrigins(handle, actionSet, action)  -> table
Storefront.Input.GetGlyphSVGForActionOrigin(origin)                 -> string
Storefront.Input.GetStringForActionOrigin(origin)                   -> string
```

**Источник** (origin) — это конкретный физический ввод (например, «кнопка A», «правый триггер»), к которому действие в
данный момент привязано на конкретном устройстве. Используйте источники, чтобы рисовать корректные экранные подсказки
(«Нажмите Ⓐ, чтобы прыгнуть»), соответствующие реальному контроллеру и привязкам игрока.

- `GetDigitalActionOrigins` / `GetAnalogActionOrigins` возвращают массив (индексация от 1) целочисленных id источников
  для данного контроллера + набора действий + действия.
- `GetGlyphSVGForActionOrigin(origin)` возвращает абсолютный путь к файлу **SVG-глифа** для этого источника (для
  отрисовки иконки кнопки).
- `GetStringForActionOrigin(origin)` возвращает читаемое имя источника (например, `"A"`, `"Right Trigger"`).

```lua
local jump = Storefront.Input.GetDigitalActionHandle("Jump")
local set  = Storefront.Input.GetActionSetHandle("InGameControls")
local origins = Storefront.Input.GetDigitalActionOrigins(controller, set, jump)
if #origins > 0 then
    local label = Storefront.Input.GetStringForActionOrigin(origins[1])
    local glyph = Storefront.Input.GetGlyphSVGForActionOrigin(origins[1])
    ShowPrompt("Нажмите " .. label .. ", чтобы прыгнуть", glyph)
end
```

## 16. Служебные функции платформы

Помощники для устройства, окружения, изображений и экранной клавиатуры. Они специфичны для Steam.

### 16.1 Запросы об устройстве и окружении

```lua
Storefront.IsSteamDeck()       -> bool   -- работает на Steam Deck
Storefront.IsSteamMachine()    -> bool   -- работает на Steam Machine
Storefront.IsSteamFrame()      -> bool   -- работает на Steam Frame
Storefront.GetSteamHardware()  -> int    -- Storefront.SteamHardware.* (0, если это не железо Steam)
Storefront.GetHardwareDefaultConfig() -> int  -- Storefront.HardwareConfig.*
Storefront.IsRunningUnderProton()     -> bool  -- запущено через Proton на Linux
Storefront.IsBigPictureMode()  -> bool   -- активен режим Steam Big Picture
Storefront.IsRunningInVR()     -> bool   -- запущено в режиме Steam VR
Storefront.GetBatteryPower()   -> int    -- заряд батареи % (0–100), или 255 при питании от сети / неизвестно
```

Используйте их, чтобы адаптировать масштаб интерфейса, переключаться на ввод с контроллера по умолчанию или показывать
предупреждения о батарее на Deck.

```lua
if Storefront.IsSteamDeck() then
    UseControllerUI()
    UseLargerFonts()
end

local bat = Storefront.GetBatteryPower()
if bat ~= 255 and bat <= 15 then
    ShowToast("Низкий заряд батареи: " .. bat .. "%")
end
```

**Выбор графических настроек по умолчанию на железе Steam.** `GetSteamHardware()` говорит, какое именно это
устройство, и предназначен для аналитики, поддержки и диагностики. Для самого *решения* — какой пресет графики
выставить при первом запуске — используйте `GetHardwareDefaultConfig()`: Valve сопоставляет его с каждым устройством
(и позволяет перенастроить сопоставление позже через партнёрский сайт Steamworks, без выпуска патча), а также
срабатывает для сторонних консолей с похожими характеристиками. Именно это позволяет сборке корректно работать на
железе Steam, которого не существовало на момент релиза.

```lua
-- Выполните один раз, при первом запуске игры на новой машине.
local cfg = Storefront.GetHardwareDefaultConfig()
local HC  = Storefront.HardwareConfig

if     cfg == HC.SteamDeck    then ApplyPreset("deck")
elseif cfg == HC.SteamMachine then ApplyPreset("machine")
elseif cfg == HC.SteamFrame   then ApplyPreset("frame")
elseif cfg == HC.Low          then ApplyPreset("low")
elseif cfg == HC.Medium       then ApplyPreset("medium")
elseif cfg == HC.High         then ApplyPreset("high")
elseif cfg == HC.Max          then ApplyPreset("ultra")
else                               ApplyPresetFromOwnHeuristics()
end
```

> **Steam Deck, Steam Machine и Steam Frame.** `Storefront.IsSteamDeck()` работает точно так же, как раньше, но
> теперь выводится из запроса устройства, который заменил удалённый `ISteamUtils::IsRunningOnSteamDeck()` в
> Steamworks SDK **v1.65**, и потому знает также про Steam Machine и Steam Frame. Когда решение касается
> *возможности*, а не отчётности, предпочитайте проверки возможностей (`GetHardwareDefaultConfig()`,
> `IsBigPictureMode()`, `Storefront.Input.GetControllers()`, `GetBatteryPower()`) вместо проверок конкретного устройства.

### 16.10 Отчёт о ваших графических настройках в Steam

```lua

```

отражение [`GetHardwareDefaultConfig()`](#161-запросы-об-устройстве-и-окружении): тот спрашивает у Steam, с чего
начать, а эти два сообщают обратно, на чём вы остановились.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `setting` | `int` | Значение [`PerformanceSetting`](#performancesetting-enum) |

использует их, чтобы настраивать, что `GetHardwareDefaultConfig()` возвращает для вашей игры на будущем железе.
Отчитываться ничего не стоит, а игра будет лучше вести себя на устройствах Steam, которых ещё не существует.

```lua
function ApplyPreset(name, w, h)
    -- ... применяем собственные настройки ...
    if not Storefront.IsAvailable() then return end
    local PS = Storefront.PerformanceSetting
    local map = { low = PS.Low, medium = PS.Medium, high = PS.High, ultra = PS.Ultra }
    Storefront.SetGamePerformanceSetting(map[name] or PS.Custom)
    Storefront.SetGameRenderResolution(w, h)
end
```

<a id="17-authentication-tickets"></a>
## 17. Билеты аутентификации

Билеты аутентификации позволяют вашему бэкенду проверять идентичность игрока в Steam и право владения. Оба запроса
асинхронны и доставляют байты билета в колбэк. Специфично для Steam.

> Билеты — это бинарные блобы, возвращаемые в виде строк Lua. Отправляйте их на свой сервер, который проверяет их с
> помощью веб-API Steam. Не доверяйте заявлениям клиента об идентичности без проверенного билета.

### 17.1 Storefront.RequestAuthSessionTicket

```lua
Storefront.RequestAuthSessionTicket(callback)
```

Запрашивает **билет сессии**, подтверждающий идентичность локального пользователя в Steam (используется для
аутентификации на игровом сервере или бэкенде).

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `callback` | `function(result, ticket, handle)` | `ticket` — байты билета (строка) или `nil` при неудаче; `handle` — дескриптор билета для [`CancelAuthSessionTicket`](#173-storefrontcancelauthsessionticket) |

```lua
Storefront.RequestAuthSessionTicket(function(r, ticket, handle)
    if r == Storefront.Result.Ok and ticket then
        myTicketHandle = handle
        SendToServerForValidation(ticket)
    end
end)
```

> Колбэк срабатывает только после того, как **Steam подтвердит билет** на своих серверах — билет, выданный раньше
> этого момента, был бы отклонён вызовом `BeginAuthSession` на принимающей стороне. Ожидайте его через несколько
> кадров (или, при медленном соединении, через несколько секунд) после вызова. Если проверка не прошла, колбэк всё
> равно вызывается — с кодом ошибки и без билета.

---

### 17.2 Storefront.RequestEncryptedAppTicket

```lua
Storefront.RequestEncryptedAppTicket(userData, callback)
```

Запрашивает **зашифрованный билет приложения** — защищённый от подделки токен (расшифровываемый только секретным ключом
вашего приложения на вашем сервере), несущий информацию о владении плюс ваши собственные данные `userData`.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `userData` | `string` \| `table` | Произвольные байты для встраивания в билет (строка или массив `0–255`) |
| `callback` | `function(result, ticket)` | `ticket` — зашифрованные байты (строка) или `nil` при неудаче |

```lua
Storefront.RequestEncryptedAppTicket("session:" .. mySessionId, function(r, ticket)
    if r == Storefront.Result.Ok and ticket then
        SendToServer(ticket)
    end
end)
```

> Steam ограничивает частоту запросов зашифрованных билетов приложения (примерно раз в несколько секунд) — запрашивайте
> один билет на сессию и кешируйте его.

### 17.3 Storefront.CancelAuthSessionTicket

```lua
Storefront.CancelAuthSessionTicket(handle)
```

Говорит Steam аннулировать ранее выданный билет сессии аутентификации (например, когда игрок отключается от вашего
сервера). `handle` — это третье значение, полученное колбэком
[`RequestAuthSessionTicket`](#171-storefrontrequestauthsessionticket).

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `handle` | `int` | Хэндл билета аутентификации для отмены |

```lua

    Storefront.CancelAuthSessionTicket(myTicketHandle)
    myTicketHandle = nil
end
```

### 17.4 Storefront.RequestWebApiAuthTicket

```lua
Storefront.RequestWebApiAuthTicket(identity, callback)
```

Запрашивает у Steam билет, предназначенный для **вашего собственного веб-бэкенда**, который проверяет его вызовом
web API Steam `ISteamUserAuth/AuthenticateUserTicket`. Асинхронно.

> **Именно это нужно для сервера.** Билет из
> [`RequestAuthSessionTicket`](#171-storefrontrequestauthsessionticket) предназначен только для
> peer-to-peer [`BeginAuthSession`](#175-storefrontbeginauthsession) — в заголовке Valve прямо написано, что с web
> API он *не сработает*. Если вы доказываете вашему бэкенду, что «этот игрок действительно этот SteamID», вам нужна
> эта функция.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `identity` | `string` | Необязательно. Строка, идентифицирующая сервис, для которого билет; передавайте то же значение, что использует ваш бэкенд при проверке |
| `callback` | `function(result, ticket, handle)` | `ticket` — бинарная строка, `handle` нужен для последующей отмены |

```lua
Storefront.RequestWebApiAuthTicket("my-game-backend", function(r, ticket, handle)
    if r ~= Storefront.Result.Ok then return end
    myTicketHandle = handle
    -- Кодируем в hex и отправляем бэкенду, который вызовет AuthenticateUserTicket.
    local hex = (ticket:gsub(".", function(c) return string.format("%02X", c:byte()) end))
    SendLoginRequest(hex)
end)
```

Отменяйте через [`CancelAuthSessionTicket`](#173-storefrontcancelauthsessionticket) по окончании сессии.

---

### 17.5 Storefront.BeginAuthSession

```lua
Storefront.BeginAuthSession(ticket, user) -> int
```

Начинает проверку билета, который **прислал вам пир**, — сторона хоста в P2P-сессии. Возвращает
[`AuthSessionResult`](#authsessionresult-enum) **синхронно**, и это говорит лишь о том, принял ли Steam билет к
проверке. Настоящий вердикт приходит позже в
[`OnAuthSessionValidated`](#197-storefrontonauthsessionvalidated).

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `ticket` | `string` | Бинарный билет, присланный пиром, ровно как получен |
| `user` | `table` | [`UserHandle`](#userhandle-table-ref) пира, который его прислал |

```lua
function OnPeerHello(peer, ticket)
    local r = Storefront.BeginAuthSession(ticket, peer.user)
    if r ~= Storefront.AuthSessionResult.Ok then
        Disconnect(peer, "плохой билет")
    end
    -- Теперь ждём OnAuthSessionValidated, прежде чем доверять.
end

Storefront.OnAuthSessionValidated(function(user, owner, response)
    if response ~= Storefront.AuthSessionResponse.Ok then
        Disconnect(FindPeer(user), Storefront.ResultName(response))
        return
    end
    -- `owner` отличается от `user`, когда игра получена по Family Sharing.
    if Storefront.UserHasLicenseForApp(user, Storefront.GetAppId())
            ~= Storefront.LicenseResult.HasLicense then
        Disconnect(FindPeer(user), "не владеет игрой")
        return
    end
    Admit(FindPeer(user))
end)
```

Всегда парьте с [`EndAuthSession`](#176-storefrontendauthsession) — Steam отслеживает пользователя, пока вы этого
не сделаете.

---

### 17.6 Storefront.EndAuthSession

```lua
Storefront.EndAuthSession(user)
```

Прекращает отслеживание, начатое [`BeginAuthSession`](#175-storefrontbeginauthsession). Вызывайте сразу, как пир
уходит, включая аварийный разрыв, — иначе Steam держит сессию открытой, и следующий `BeginAuthSession` этого пира
вернёт `DuplicateRequest`.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `user` | `table` | [`UserHandle`](#userhandle-table-ref) пира |

### 17.7 Storefront.UserHasLicenseForApp

```lua
Storefront.UserHasLicenseForApp(user, appId) -> int
```

После успешного `BeginAuthSession` спрашивает, владеет ли этот пользователь указанным приложением или DLC.
Возвращает [`LicenseResult`](#licenseresult-enum).

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `user` | `table` | [`UserHandle`](#userhandle-table-ref) аутентифицированного пира |
| `appId` | `int` | Id приложения или DLC для проверки |

Возвращает `NoAuth`, если вы не вызывали для этого пользователя `BeginAuthSession` — обычная причина, по которой
это выглядит сломанным.

### 18.5 Storefront.RestartAppIfNecessary

## 19. События и колбэки

Часть активности Steam **проталкивается** вам, а не опрашивается: входящее P2P-сообщение, строка чата лобби, друг,
принимающий приглашение. Зарегистрируйте функцию-обработчик для каждого интересующего вас события. **Обработчики
срабатывают в главном потоке, во время [покадрового сброса очереди](#the-frame-tick--storefronttick) плагином** —
вызывать тик для этого не нужно.

Регистрация обработчика заменяет любой предыдущий для этого события. Регистрировать можно в любое время (плагин
переустанавливает обработчики, когда бэкенд становится активным). Передавайте функции без `nil`; чтобы перестать
получать события, зарегистрируйте пустую функцию.

| Регистрация | Сигнатура обработчика |
|--------------|-------------------|
| `Storefront.OnP2PMessage(fn)` | `fn(message)` |
| `Storefront.OnLobbyChat(fn)` | `fn(lobbyId, sender, payload)` |
| `Storefront.OnLobbyMemberChanged(fn)` | `fn(lobbyId, user, joined)` |
| `Storefront.OnAchievementUnlocked(fn)` | `fn(achievement)` |
| `Storefront.OnOverlayActivated(fn)` | `fn(active)` |
| `Storefront.OnConnectInvite(fn)` | `fn(connectString)` |
| `Storefront.SetLogSink(fn)` | `fn(level, message)` |

### 19.1 Storefront.OnP2PMessage

```lua
Storefront.OnP2PMessage(function(message) ... end)
```

Вызывается для каждого входящего [P2P-сообщения](#p2pmessage-table). **Пока обработчик зарегистрирован, сообщения
доставляются сюда и не ставятся в очередь для [`ReceiveP2P`](#112-storefrontreceivep2p).** `message` — это таблица
[`P2PMessage`](#p2pmessage-table) (`sender`, `channel`, `payload`).

```lua
Storefront.OnP2PMessage(function(msg)
    HandlePacket(msg.sender, msg.channel, msg.payload)
end)
```

---

### 19.2 Storefront.OnLobbyChat

```lua
Storefront.OnLobbyChat(function(lobbyId, sender, payload) ... end)
```

Вызывается при получении чат-сообщения лобби (отправленного через [`SendLobbyChat`](#107-storefrontsendlobbychat)).

| Аргумент | Тип | Описание |
|----------|------|-------------|
| `lobbyId` | `int` | Лобби, в котором было отправлено сообщение |
| `sender` | `table` | [`UserHandle`](#the-userhandle-table) отправителя |
| `payload` | `string` | Байты сообщения |

```lua
Storefront.OnLobbyChat(function(lobbyId, sender, text)
    Print(sender.textId .. ": " .. text)
end)
```

---

### 19.3 Storefront.OnLobbyMemberChanged

```lua
Storefront.OnLobbyMemberChanged(function(lobbyId, user, joined) ... end)
```

Вызывается, когда участник присоединяется к лобби, в котором вы находитесь, или покидает его.

| Аргумент | Тип | Описание |
|----------|------|-------------|
| `lobbyId` | `int` | Лобби |
| `user` | `table` | [`UserHandle`](#the-userhandle-table) участника |
| `joined` | `bool` | `true`, если присоединился, `false`, если ушёл/отключился/был исключён |

```lua
Storefront.OnLobbyMemberChanged(function(lobbyId, user, joined)
    Print(user.textId .. (joined and " присоединился" or " вышел"))
    RefreshLobbyRoster(lobbyId)
end)
```

### 19.4 Storefront.OnAchievementUnlocked

```lua
Storefront.OnAchievementUnlocked(function(achievement) ... end)
```

Вызывается всякий раз, когда разблокируется достижение (в том числе из `UnlockAchievement` или когда Steam
разблокирует достижение по прогрессу). `achievement` — это таблица [`Achievement`](#achievement-table). Удобно для
вашего собственного внутриигрового празднования поверх всплывающего уведомления Steam.

```lua
Storefront.OnAchievementUnlocked(function(a)
    PlaySound("fanfare")
    ShowBanner("Достижение: " .. a.displayName)
end)
```

### 19.5 Storefront.OnOverlayActivated

```lua
Storefront.OnOverlayActivated(function(active) ... end)
```

Вызывается, когда оверлей Steam открывается или закрывается. Ставьте игру на паузу, пока оверлей открыт.

| Аргумент | Тип | Описание |
|----------|------|-------------|
| `active` | `bool` | `true`, когда оверлей открылся, `false`, когда закрылся |

```lua
Storefront.OnOverlayActivated(function(active)
    SetPaused(active)
end)
```

### 19.6 Storefront.OnConnectInvite

```lua
Storefront.OnConnectInvite(function(connectString) ... end)
```

Вызывается, когда игрок принимает **приглашение** Steam или запускает игру через параметр **+connect** /
«Присоединиться к игре» из Rich Presence. Это точка входа для сценариев *присоединиться к игре друга*. `connectString`
— это то, что задал пригласивший (например, `"+connect_lobby <lobbyId>"` из приглашения в лобби, или ваша собственная
строка подключения).

```lua
Storefront.OnConnectInvite(function(connect)
    local lobbyId = Storefront.ParseConnectLobby(connect)
    if lobbyId then
        Storefront.JoinLobby(lobbyId, function(r, lobby) end)
    end
end)
```

#### Две половины «Присоединиться к игре»

Приглашение доходит до вашей игры **одним из двух путей**, и игра, реализовавшая только один из них, в половине
случаев выглядит сломанной:

| Игрок нажимает «Присоединиться»… | …а игра | Приглашение приходит как |
|---|---|---|
| в списке друзей или оверлее | **уже запущена** | этот обработчик |
| в списке друзей или оверлее | **не запущена** | командная строка процесса — Steam запускает вашу игру с добавленным `+connect_lobby <id>` |

Плагин обрабатывает оба пути и в обоих случаях даёт одну и ту же форму. На старте он разбирает собственную командную
строку (и параметры запуска Steam) и сохраняет найденное; заберите это один раз через `GetPendingConnect()`:

```lua
Storefront.GetPendingConnect()  -> string | nil   -- вернёт один раз и забудет
Storefront.PeekPendingConnect() -> string | nil   -- то же значение, без изъятия
Storefront.ParseConnectLobby(connectString) -> int | nil
```

Если на момент прихода приглашения в работающей игре обработчик `OnConnectInvite` **не** зарегистрирован,
приглашение сохраняется как отложенное — так что игра, которая только опрашивает, тоже работает. Зарегистрируйте
обработчик — и отложенный слот для живых приглашений использоваться не будет. Одно и то же приглашение вы никогда не
получите дважды.

```lua
local function Join(connect)
    local lobbyId = Storefront.ParseConnectLobby(connect)
    if lobbyId then Storefront.JoinLobby(lobbyId, function(r, lobby) end) end
end

function OnCreate()
    if not Storefront.IsAvailable() then return end
    Storefront.OnConnectInvite(Join)          -- «горячий» путь: игра уже запущена
    local pending = Storefront.GetPendingConnect()
    if pending then Join(pending) end         -- «холодный» путь: запуск из приглашения
end
```

`ParseConnectLobby` вытаскивает id лобби из строки `+connect_lobby <id>` и возвращает `nil` для всего остального —
собственное значение `connect` из Rich Presence проходит нетронутым, разбирайте его сами.

### 19.7 Storefront.OnAuthSessionValidated

```lua
Storefront.OnAuthSessionValidated(function(user, owner, response) ... end)
```

Вердикт по билету, отправленному вами через [`BeginAuthSession`](#175-storefrontbeginauthsession). Специфично для
Steam.

| Аргумент | Тип | Описание |
|----------|------|-------------|
| `user` | `table` | [`UserHandle`](#userhandle-table-ref) пользователя, чей билет проверялся |
| `owner` | `table` | [`UserHandle`](#userhandle-table-ref) аккаунта, который **владеет** игрой — отличается от `user` при Family Sharing |
| `response` | `int` | Значение [`AuthSessionResponse`](#authsessionresponse-enum); всё, кроме `Ok`, означает отказ |

Это может сработать **повторно** для уже допущенного пользователя — Steam перепроверяет при изменениях, например
когда билет отменён или аккаунт вошёл в другом месте. Обрабатывайте как смену состояния, а не как одноразовое
событие: выкидывайте игрока, у которого `response` посреди сессии стал не `Ok`.

---

### 19.8 Storefront.SetLogSink

```lua
Storefront.SetLogSink(function(level, message) ... end)
```

Перенаправляет внутренние диагностические строки лога плагина в вашу функцию — полезно для вывода проблем
инициализации/работы Steam в вашей собственной консоли.

| Аргумент | Тип | Описание |
|----------|------|-------------|
| `level` | `int` | `0` = информация, `1` = предупреждение, `2` = ошибка |
| `message` | `string` | Текст лога |

```lua
Storefront.SetLogSink(function(level, msg)
    Print("[Steam:" .. level .. "] " .. msg)
end)
```

> Сток **дополняющий**: те же строки всегда попадают и в лог движка, поэтому вы не потеряете диагностику Steam, если
> не установили свой обработчик, а установка обработчика не заглушает лог движка. В отличие от остальных обработчиков,
> сток вызывается сразу в том же кадре, когда сообщение появилось, а не откладывается до `Storefront.Tick()`.

<a id="20-steam-timeline--game-recording"></a>
## 20. Steam Timeline и запись игры

Steam Timeline — это то, что превращает записанную сессию в нечто, по чему игрок может ориентироваться: полоса
под таймлайном записи игры Steam **окрашивается по игровому режиму**, **размечается вашими событиями** и
**разбивается на фазы**. Всё это — необязательное оформление поверх записи, которую игрок может и не вести;
вызовы бесплатно превращаются в no-op, когда функция недоступна, так что ветвиться по ней не нужно.

Всё это живёт в **`Storefront.Timeline`**.

```lua
Storefront.Timeline.IsAvailable() -> bool
```

`true`, когда запущенный клиент Steam предоставляет интерфейс Timeline. Всё, что ниже, безопасно вызывать в любом
случае; это нужно только чтобы спрятать переключатель «клипы Steam» в собственном интерфейсе.

---

### 20.1 Игровой режим — окраска таймлайна

```lua
Storefront.Timeline.SetGameMode(mode)
```

Сообщает Steam, какого рода активность сейчас на экране, и этим окрашивает соответствующий отрезок записи.
Выставляйте при каждой смене состояния и не трогайте между ними — это режим, а не событие.

| Параметр | Тип | Описание |
|-----------|------|-------------|
| `mode` | `int` | Значение [`TimelineGameMode`](#timelinegamemode-enum) |

```lua
function OnMainMenuEnter()  Storefront.Timeline.SetGameMode(Storefront.TimelineGameMode.Menus) end
function OnLevelLoadBegin() Storefront.Timeline.SetGameMode(Storefront.TimelineGameMode.LoadingScreen) end
function OnLevelStart()     Storefront.Timeline.SetGameMode(Storefront.TimelineGameMode.Playing) end
function OnInventoryOpen()  Storefront.Timeline.SetGameMode(Storefront.TimelineGameMode.Staging) end
```

---

### 20.2 Подсказки

```lua
Storefront.Timeline.SetTooltip(description, timeDelta)   -- timeDelta необязателен, по умолчанию 0
Storefront.Timeline.ClearTooltip(timeDelta)              -- timeDelta необязателен, по умолчанию 0
```

Задаёт текст, который Steam показывает при наведении на текущую точку таймлайна. `timeDelta` сдвигает момент,
к которому относится изменение, в секундах **в прошлое** — используйте, если заметили смену состояния на кадр-другой
позже.

```lua
Storefront.Timeline.SetTooltip("Босс: Полый Король — фаза 2")
```

---

### 20.3 События

**Мгновенное** событие — это одна метка; **интервальное** покрывает отрезок времени. Оба принимают `iconPriority`
(0–1000, при совпадении меток побеждает больший) и `clipPriority`, который говорит Steam, насколько настойчиво
предлагать этот момент как клип.

```lua
Storefront.Timeline.AddInstantaneousEvent(args) -> int   -- хэндл события, 0 при ошибке
Storefront.Timeline.AddRangeEvent(args)         -> int
Storefront.Timeline.StartRangeEvent(args)       -> int
Storefront.Timeline.UpdateRangeEvent(event, args)
Storefront.Timeline.EndRangeEvent(event, endOffsetSeconds)   -- смещение необязательно, по умолчанию 0
Storefront.Timeline.RemoveEvent(event)
```

`args` — таблица:

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `title` | `string` | `""` | Короткая подпись на таймлайне |
| `description` | `string` | `""` | Более длинный текст при наведении |
| `icon` | `string` | `""` | Имя иконки от Steam либо одна из загруженных иконок таймлайна вашего приложения |
| `iconPriority` | `int` | `0` | 0–1000; больший выживает, когда Steam приходится прореживать метки |
| `startOffsetSeconds` | `float` | `0` | На сколько секунд **в прошлом** событие произошло на самом деле |
| `duration` | `float` | `0` | Только `AddRangeEvent`; Steam ограничивает 600 секундами |
| `clipPriority` | `int` | `None` | Значение [`TimelineClipPriority`](#timelineclippriority-enum) |

Используйте `AddRangeEvent`, когда длительность уже известна, и `StartRangeEvent` / `EndRangeEvent`, когда нет.
Сохраняйте хэндл из `StartRangeEvent` — именно его принимают `UpdateRangeEvent`, `EndRangeEvent` и `RemoveEvent`.

```lua
-- Одиночная метка на убийство.
Storefront.Timeline.AddInstantaneousEvent({
    title = "Босс повержен", description = "Полый Король",
    icon = "steam_achievement", iconPriority = 900,
    clipPriority = Storefront.TimelineClipPriority.Featured,
})

-- Интервал, который длится столько же, сколько бой.
local fight = nil
function OnBossFightStart()
    fight = Storefront.Timeline.StartRangeEvent({
        title = "Бой с боссом", icon = "steam_combat", iconPriority = 800,
        clipPriority = Storefront.TimelineClipPriority.Standard,
    })
end
function OnBossFightEnd()
    if fight then Storefront.Timeline.EndRangeEvent(fight); fight = nil end
end
```

---

### 20.4 Игровые фазы

**Фаза** — это более крупный кусок, чем событие: забег, матч, подземелье. Steam группирует запись по фазам и
позволяет игроку переключаться между ними, а фазы несут **теги** и **атрибуты**, которые становятся
метаданными записи, доступными для поиска.

```lua
Storefront.Timeline.StartGamePhase()
Storefront.Timeline.EndGamePhase()
Storefront.Timeline.SetGamePhaseId(phaseId)                     -- ваш собственный id, максимум 64 символа
Storefront.Timeline.AddGamePhaseTag(tagName, tagIcon, tagGroup, priority)
Storefront.Timeline.SetGamePhaseAttribute(group, value, priority)
Storefront.Timeline.OpenOverlayToGamePhase(phaseId)
Storefront.Timeline.OpenOverlayToEvent(event)
```

Давайте каждой фазе id, который вы сможете восстановить позже (сид забега, id матча) — именно его вы передаёте в
`OpenOverlayToGamePhase`, чтобы из собственного интерфейса отправить игрока прямо к этой записи.

```lua
function OnRunStart(seed)
    Storefront.Timeline.StartGamePhase()
    Storefront.Timeline.SetGamePhaseId("run-" .. seed)
    Storefront.Timeline.AddGamePhaseTag("Кошмар", "steam_difficulty", "Сложность", 100)
end

function OnRunEnd(kills)
    Storefront.Timeline.SetGamePhaseAttribute("Убийства", tostring(kills), 100)
    Storefront.Timeline.EndGamePhase()
end
```

> **Ничего из этого не требует, чтобы игрок вёл запись.** Если запись игры выключена или клиент Steam старше
> интерфейса Timeline, каждый вызов выше — бесплатный no-op. Размечайте смело.

<a id="24-troubleshooting--faq"></a>
## 24. Решение проблем и FAQ

**`Storefront.IsAvailable()` возвращает `false`.**
Плагин не инициализировал бэкенд. Частые причины: не настроен AppId (создайте `steam_config.json` с
`{"AppId": <id>}` в папке плагина или задайте `ICEBOX_STEAM_APPID`); клиент Steam не запущен; аккаунт, под которым
выполнен вход, не владеет AppId; либо это не настольная сборка (Android/iOS/Web — плагин работает только на настольных
платформах). С тестовым AppId `480` убедитесь, что вы владеете Spacewar (в том числе бесплатно) или что во время
разработки существует `steam_appid.txt`. Лог движка всегда сообщает, какая именно это была причина — ищите строки
`[Steam]`.

Пока бэкенда нет, плагин **повторяет попытку не чаще раза в пять секунд**, поэтому достаточно запустить клиент
Steam уже после игры или редактора: в логе появится `[Steam] SteamAPI connected on retry`, а `IsAvailable()` начнёт
возвращать `true`. Создание `steam_config.json` задним числом работает так же — перезапускать ничего не нужно.
Каждая отдельная причина отказа пишется в лог один раз, а не на каждую попытку.

Повтор выполняется из покадрового обновления плагина, которое движок вызывает, **пока работает рантайм** — в
редакторе это режим Play, а не режим редактирования. В выпущенной игре рантайм работает всегда. Поэтому в
редакторе: запустите Steam, войдите в режим Play — и бэкенд подключится в течение пяти секунд.

**Скрипты падают с «attempt to index a nil value (global 'Storefront')».**
Либо плагин не включён в **Tools → Plugins & Mods**, либо в логе движка есть строка `[Steam] Lua ABI mismatch`.
Плагин линкуется с тем же самым Lua, что и движок, и версии обязаны совпадать — плагин, собранный против
устаревшего дерева зависимостей, отказывается регистрироваться, а не роняет редактор. Скачайте релиз плагина,
собранный под **вашу** версию движка — в описании каждого релиза указано, под какую именно, — и замените
библиотеку плагина. Пересобрать самостоятельно нельзя: исходный код не публикуется.

**Мои колбэки / события никогда не срабатывают.**
Очередь сбрасывается из шага обновления плагина в движке, а он работает только пока запущен **рантайм** — в
редакторе это режим Play, а не режим редактирования. Проверьте, что плагин включён в `Config/Plugins.json`, что
`Storefront.IsAvailable()` возвращает `true` и что сам колбэк не вызывает ошибку Lua (ошибки внутри колбэка
проглатываются защищённым вызовом). Ручной [`Storefront.Tick()`](#the-frame-tick--storefronttick) в `OnUpdate`
скрипта уровня не помешает, но он больше не является тем, что заставляет колбэки срабатывать.

**`ReceiveP2P()` всегда возвращает `nil`, хотя сообщения приходят.**
Вы зарегистрировали обработчик [`OnP2PMessage`](#191-storefrontonp2pmessage). Пока обработчик установлен, сообщения
доставляются ему и не ставятся в очередь для опроса — используйте один механизм или другой.

**Достижения разблокируются в коде, но я не вижу всплывающего уведомления.**
Оверлей Steam должен быть включён, а игра — запущена через Steam. Также подтвердите, что **API-имя** достижения (а не
отображаемое имя) указано верно и что статистика завершила синхронизацию — чтения берутся из кеша, заполняемого вскоре
после инициализации.

**`globalUnlockPercent` равен `-1`.**
Глобальная статистика ещё не пришла. Плагин запрашивает её при инициализации; вызовите
[`RequestGlobalAchievementPercentages`](#164-storefrontrequestglobalachievementpercentages) и прочитайте значение через
несколько кадров.

**Аватары друзей / иконки достижений возвращают `nil`.**
Steam загружает изображения асинхронно. Первый вызов запрашивает изображение; получите пиксели снова через кадр-другой,
когда оно загрузится.

**Данные лобби, заданные участником, не видны другим.**
Метаданные лобби, которые читают другие игроки, должен задавать **владелец** лобби. Персональные данные участника — это
отдельное.

**Нужно ли мне самому вызывать `SteamAPI_RunCallbacks`?**
Нет. Плагин каждый кадр автоматически прокачивает нативные колбэки Steam и сбрасывает очередь результатов в Lua.
`Storefront.Tick()` нужен только если вы хотите, чтобы сброс происходил в конкретной точке вашего кадра.

**Ломаются ли эти скрипты на Android / iOS / Web?**
Нет — плагина там просто нет, поэтому `Storefront.IsAvailable()` возвращает `false`, и каждый вызов является безопасной
пустой операцией. Защита через `IsAvailable()` сохраняет работу одного скрипта на всех платформах.

<a id="25-visual-scripting-nodes"></a>
## 25. Ноды визуального скриптинга

Плагин поставляет собственный каталог визуального скриптинга — `VisualScriptAPI.json` в корне плагина. Редактор
IceBox автоматически загружает такие каталоги из папки каждого плагина, поэтому при наличии Steam-плагина весь
API `Storefront` также доступен в виде нод в редакторе визуальных скриптов. Никакой настройки движка не требуется.

### Что вы получаете

- **Нода для каждой функции** `Storefront`, `Storefront.Workshop` и `Storefront.Input`, сгруппированные по
  категориям в палитре нод: *Steam*, *Steam Achievements*, *Steam Stats*, *Steam Leaderboards*, *Steam Cloud*,
  *Steam Lobby*, *Steam P2P*, *Steam DLC*, *Steam Overlay*, *Steam Voice*, *Steam Friends*, *Steam Auth*,
  *Steam Device*, *Steam Events*, *Steam Workshop*, *Steam Input*.
- **Выпадающие списки перечислений.** Аргументы, за которыми стоит перечисление `Storefront` (тип лобби,
  сортировка / отображение / метод загрузки таблиц лидеров, диапазон выборки, канал и тип отправки P2P, режим
  экранной клавиатуры, коды результата), получают пикер с полными выражениями `Storefront.<Enum>.<Value>` и уже
  выбранным разумным значением по умолчанию.
- **Несколько возвращаемых значений.** Функции, возвращающие несколько значений, дают по выходному пину на
  каждое — у `Get Stat Int` есть пины `Value` и `Result`, у `Get Image RGBA` — `Data`, `Width` и `Height`,
  у `Decompress Voice` — `Result`, `Data` и `SampleRate`, и так далее.
- **Чистые геттеры.** Вызовы только для чтения (`Is Logged In`, `Get Persona Name`, `Cloud List`, …) — это
  чистые ноды без exec-пинов: подключайте их выходы напрямую к другим входам.
- **Колбэки.** Асинхронные функции имеют пин `Callback`. Создайте в графе Custom Event и подайте его через ноду
  **Function Reference** во вход `Callback` — событие сработает с теми же аргументами, что получил бы
  Lua-колбэк.

Золотое правило из [§3](#the-frame-tick--storefronttick) остаётся в силе: запускайте ноду **Tick** (категория
*Steam Events*) каждый кадр — например, после `On Update` — иначе поставленные в очередь результаты и колбэки
событий никогда не придут.

### Откуда берётся каталог

`VisualScriptAPI.json` лежит в папке плагина рядом с `plugin.json` и генерируется из Lua-биндингов плагина перед
каждым релизом — поэтому он всегда соответствует библиотеке, с которой приехал. Редактор читает его прямо из папки
плагина: устанавливать, настраивать или перегенерировать нечего.

Он выглядит артефактом сборки, но это не он: **это обязательный файл данных времени выполнения.** Удалите его — и
все ноды `Storefront` молча исчезнут из палитры, без единой ошибки где бы то ни было. Держите его вместе с
плагином и заменяйте вместе с библиотекой, когда берёте новый релиз.
